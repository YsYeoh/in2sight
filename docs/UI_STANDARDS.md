# UI standards (in2sight)

Every screen follows these rules. They come from the UX polish pass (design: docs/superpowers/specs/2026-10-20-ux-polish-and-tabs-design.md; built in Plan 14a). Each rule names the piece that implements it: use that piece, do not build a new one. `/styleguide` → "Standard controls" shows every piece in the current theme. Guards: `tests/ui-standards.test.ts`, `tests/messages.test.ts`, `tests/density-css.test.ts`, `tests/scrollbar-css.test.ts`.

1. **Few controls on screen.** At most 3–5 primary controls; everything else under "Advanced" (filters) or "More ranges" (time). Crowded filter rows confused the owner. → `FilterToolbar` (`advanced`, `advancedCount`), `RangeBar`.
2. **Hidden state is never invisible.** What is chosen inside a panel shows on its button (its name, a highlight or a count badge) and as a removable chip; "Clear all" removes the filters. → `FilterPanel` (`active`, `badge`), `FilterToolbar` (`chips`, `clearHref`), the `RangeBar` button.
3. **The URL is the state; apply as you pick.** Filters, ranges and tabs live in the URL, so links, Back and saved views keep working. A select or option navigates at once, text search after a 400 ms pause (replace, no history spam); no Apply buttons; the top progress bar is the feedback. Never reset another filter when one changes. → `useApply`, `FilterSelect`, `FilterSearch`, `FilterOptions`.
4. **The range filter belongs to trend pages only.** Overview, account Overview and Growth, Calendar, Explorer and the export dialog use `RangeBar` (on an account tab, `keep={{ tab }}`; Last 7 / 14 / 30 Days visible, the rest under "More ranges"). Lists (Posts, Stories, Tags) have their own filters in a `FilterToolbar` and never show the range bar.
5. **One control height per row.** Every button, select, input and segmented control in a row is `--ctl` high: `size="default"` buttons, `h-[var(--ctl)]` native selects. Header action rows use the default size for every button, link-buttons included. `size="sm"` only inside a segmented control or a dense table or list, never next to a default control. Sizes come from the density tokens (`styles/density.css` is un-layered: `h-*`/`p-*` on shadcn controls are ignored).
6. **Full-word labels.** "Last 7 Days", "Last 12 months", "Year to date", "All time"; never `7d`, `1y`, `YTD`, in both languages.
7. **Underline tabs for page sections.** `TabsList variant="line"`: full width on a bottom rule, the active tab underlined in `--primary`; on overflow they scroll sideways with a fade and no visible bar. The pill variant is for small in-card toggles only.
8. **One scrollbar.** `styles/scrollbar.css` styles every scroller (thin, 8 px, rounded, from `--foreground`, quiet until hover) in every theme; no per-component scrollbar styling; `scrollbar-none` only where a bar must stay hidden (tab strips).
9. **No native chrome showing through.** Native selects and date inputs take the theme's input border and background; no browser scroll arrows, no default scrollbars.
10. **Panels: a dialog on desktop, a bottom sheet on phones.** Every panel is a `ResponsiveDialog` (`FilterPanel`): focus is trapped, Esc and "Done" close it, focus returns to its button. Never `matchMedia` for layout.
11. **Tokens only.** Colours from semantic tokens, sizes from density tokens, dates and numbers through `lib/format.ts`; check light and dark of every theme.
12. **Lists page on the server.** A list that can grow (Posts, Stories) reads one page at a time: `Pagination` (First / Previous / "Page X of Y" / Next / Last, every link from `hrefFor(page)` so all other params stay), a count line ("51–100 of 1,234 posts"), no "Show more". Sorting is the server's: the Sort select and the sortable table headers set the same `sort` (`DataTable` `serverSort`); a column without a server sort is not sortable. Any filter or sort change goes back to page 1; a stale page shows page 1. → `components/shared/Pagination.tsx`, `lib/dashboard/lists.ts`.
13. **Lists have their own date filter.** `PostedFilter` (quick dates + custom dates, URL `pr` / `pfrom` / `pto`), never the Time Scope; the page's Time Scope params ride along in every list link untouched. The list's Suspense boundary is not keyed by list params, so the toolbar never remounts while results stream.
14. **Analysis states its basis.** Every analysis card says where its numbers come from (a source line under the title), the sample behind any "typical" or "median" (`n`), a confidence word for rule-based findings (Low / Medium — never "high": a rule finds a pattern, not a cause) and a "data starts" line when the history is shorter than the range; a missing number has a reason, never 0. A clickable chart always has a keyboard path to the same items (a list or table), and a pick that only changes what is shown is URL state written with `history.replaceState` (no server round trip). → `ChartCard` `subtitle`, `WhyPanel`, `GrowthTab`.
15. **Uploads are parsed in the browser and re-checked on the server.** A file the owner picks is size-checked by name and size BEFORE it is read, parsed by a pure, capped, shape-validating function (JSON.parse only, error keys, odd entries skipped and counted), previewed, and only the minimum the feature needs is sent — to a route handler that checks the owner, the origin, the content type and the byte size before reading, reads with a byte cap and validates every value again. Raw files never leave the device; nothing from them is logged. → `lib/followers/parse.ts`, `lib/followers/payload.ts`, `app/api/accounts/[id]/followers/route.ts`, `components/account/FollowerUpload.tsx`.
16. **Third-party text is text.** Comments, captions and names from other people are rendered as React text (never `dangerouslySetInnerHTML`), length-capped in lists (`capText`, emoji never split) with `break-words`, and never put in a URL; what the owner types into a search box may appear in request logs, so the runbook says so. → `components/account/CommentRow.tsx`, `lib/comments/view.ts`, `tests/comments-privacy.test.ts`.

17. **Writes to Instagram are confirmed, logged and reversible where Instagram allows.** Every action that changes something on Instagram opens a confirm (`ConfirmDialog`; an irreversible one needs a typed word via `requireText` and says it cannot be undone), sends one request per dialog opening (a request id the server refuses to repeat), keeps the button busy while it runs, announces the result (`role="status"`), shows errors as translated keys (`role="alert"`), returns focus to the button that opened it, and appears in the moderation log with Undo where possible. Automation never deletes. → `components/account/CommentActions.tsx` (`useModerationRun`), `lib/moderation/service.ts`.

**A new list page:** a `FilterToolbar` with the 3–5 filters people use most, the rest in `advanced`, chips and Clear all, every parameter validated on the server (parse/serialise helpers like `lib/dashboard/lists.ts`), server pages with `Pagination`. **A new trend page:** `RangeBar` and `parseTimeScope`/`resolveScope`.
