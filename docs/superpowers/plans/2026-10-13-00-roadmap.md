# in2sight — Implementation Roadmap

**Spec:** `docs/SPEC.md` (approved 2026-10-13). Visual reference: `docs/mockups/` (run `node docs/mockups/serve.cjs`).

The spec covers eight independent subsystems, so it is built as **a sequence of plans**. Each plan produces working, testable software on its own, is executed with subagent-driven development on its own branch (`feat/<plan-name>`), gets a whole-branch review, and is merged before the next plan starts. **Only Plan 1 is written in detail now**; each later plan is written just before it runs, so it can use what the previous plans actually produced (real file names, real versions, real fixtures).

## Execution rules (all plans)

- Branch per plan: `feat/<plan-name>`; commits are small, conventional (`feat:`, `fix:`, `test:`, `docs:`, `chore:`), and end with the trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Each task: a fresh implementer subagent, then a fresh reviewer; the next task starts only after the review passes. After the last task: one whole-branch review, then merge to `main` and push (push only with the owner's go-ahead).
- TDD for logic (write failing test → see it fail → implement → see it pass). UI-only work is verified by `npm run check` plus a screenshot check against `docs/mockups/`.
- Before saying a plan is done: `npm run check` (lint + typecheck + tests + build) must pass, and TODO.md items are ticked.
- External resources (Supabase, Vercel, Meta app, push keys) are created only with the owner's explicit confirmation.

## Known risks to handle when writing later plans

- **Next.js 16:** `middleware.ts` is now `proxy.ts` (Node runtime) — relevant to Plan 3. `cookies()`, `headers()` and `params` are async.
- **TypeScript 7** is current; if a tool chokes on it, pin `typescript@5` rather than working around it.
- **Meta API metric names change** (Plan 5): verify against current docs, keep them in one constants file.
- **Recharts 3** API differs from v2 examples online; follow the installed version's docs.
