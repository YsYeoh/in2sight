# UI Kit Core Implementation Plan (Plan 2 of 8, trimmed)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The shared UI foundation every later screen is built from: shadcn/ui primitives wired to our design tokens (density, radius, themes), a few shared composition components, a responsive `AppShell` (bottom tabs → icon rail → full sidebar), a bottom-sheet-capable dialog, and a `/styleguide` gallery to eyeball them.

**Architecture:** shadcn components are copied into `components/ui/` and styled by our CSS tokens: text sizes and radii come from the Tailwind `@theme` mapping, control heights and paddings come from an un-layered `styles/density.css` keyed on shadcn's `data-slot` attributes, so density/radius/theme switch live without touching component code. Shared compositions live in `components/shared/`. Responsiveness is CSS-only (Tailwind breakpoints, `max-md:` classes) so server and client render identically.

**Tech Stack:** shadcn/ui (CLI 4.x, new-york style), Radix (`radix-ui`), lucide-react, sonner, class-variance-authority, clsx, tailwind-merge, tw-animate-css, Tailwind 4.3, next-intl, Vitest + Testing Library.

**Spec:** `docs/SPEC.md` §8b (reuse, flexible, i18n, themes, responsive). Roadmap: `docs/superpowers/plans/2026-10-13-00-roadmap.md`. **Visual reference:** `docs/mockups/` (`kit.css`, `kit-forms.html`, `kit-data.html`, `app-prototype.html`) — run `node docs/mockups/serve.cjs` and open `http://localhost:5173/?page=kit-forms` to compare.

## Review Focus

1. **shadcn defaults leaking through:** a component that keeps a hard-coded `h-9`/`text-sm`/`rounded-md` look so that switching density (Dense ↔ Comfortable) or radius (Sharp/Soft/Round) changes nothing — verify via the CSS (`styles/density.css`, `@theme`), not by eye only. *(Tasks 1-2)*
2. **`next-themes` sneaking back in:** the generated `sonner` component imports it; it must read the mode from `usePrefs()` instead, or the Toaster crashes without a provider. *(Task 2)*
3. **Hydration mismatches from responsive logic:** no `window.matchMedia`/`useMediaQuery` in render paths; layout switching is CSS-only. *(Tasks 4-5)*
4. **Navigation accessibility:** exactly one nav item marked `aria-current="page"` per landmark, landmarks labelled, links reachable by keyboard; the bottom tab bar must not cover page content (bottom padding). *(Task 5)*
5. **Form accessibility:** `FormField` ties label, hint and error to the control with matching `id`/`aria-describedby`/`aria-invalid`; an error replaces the hint visually but both stay announced. *(Task 3)*

```css
/*
 * Density overrides for shadcn components. Un-layered on purpose: un-layered CSS wins over Tailwind's
 * `@layer utilities`. Heights/paddings come from the density tokens in tokens.css (--ctl, --ctl-sm, --pc ...).
 * Selectors are keyed on data-slot / data-size, which shadcn components render.
 */
[data-slot="button"]:not([data-size="icon"]):not([data-size="icon-sm"]):not([data-size="icon-lg"]) {
  height: var(--ctl);
  padding-inline: calc(var(--ctl) * 0.4);
}
[data-slot="button"][data-size="sm"] {
  height: var(--ctl-sm);
  padding-inline: calc(var(--ctl-sm) * 0.4);
}
[data-slot="button"][data-size="icon"],
[data-slot="button"][data-size="icon-lg"] {
  width: var(--ctl);
  height: var(--ctl);
}
[data-slot="button"][data-size="icon-sm"] {
  width: var(--ctl-sm);
  height: var(--ctl-sm);
}
[data-slot="input"] {
  height: var(--ctl);
}
[data-slot="select-trigger"] {
  height: var(--ctl);
}
[data-slot="select-trigger"][data-size="sm"] {
  height: var(--ctl-sm);
}
[data-slot="textarea"] {
  padding: calc(var(--ctl) * 0.25) calc(var(--ctl) * 0.33);
}
[data-slot="table-head"] {
  height: calc(var(--row) + 4px);
}
[data-slot="table-cell"] {
  height: var(--row);
  padding-block: 0;
}
[data-slot="card"] {
  gap: var(--gp);
  padding-block: var(--pc);
}
[data-slot="card-header"],
[data-slot="card-content"],
[data-slot="card-footer"] {
  padding-inline: var(--pc);
}
[data-slot="tabs-trigger"] {
  height: var(--ctl);
}
```

```tsx
import { describe, expect, it } from 'vitest';
import { FormField } from '@/components/shared/FormField';
import { Input } from '@/components/ui/input';

const field = (props: Partial<React.ComponentProps<typeof FormField>> = {}) =>
  render(
    <FormField id="email" label="Email" {...props}>
      {(p) => <Input {...p} />}
    </FormField>,
  );

describe('FormField', () => {
  it('connects the label to the control', () => {
    field();
    expect(screen.getByLabelText('Email')).toHaveAttribute('id', 'email');
  });

  it('shows the hint and links it with aria-describedby', () => {
    field({ hint: 'We never share it' });
    const input = screen.getByLabelText('Email');
    const hint = screen.getByText('We never share it');
    expect(input.getAttribute('aria-describedby')).toBe(hint.id);
    expect(input).not.toHaveAttribute('aria-invalid', 'true');
  });

  it('an error replaces the hint, is announced, and marks the control invalid', () => {
    field({ hint: 'We never share it', error: 'Enter a valid email' });
    const input = screen.getByLabelText('Email');
    expect(screen.queryByText('We never share it')).not.toBeInTheDocument();
    const err = screen.getByRole('alert');
    expect(err).toHaveTextContent('Enter a valid email');
    expect(input.getAttribute('aria-describedby')).toBe(err.id);
    expect(input).toHaveAttribute('aria-invalid', 'true');
  });

  it('marks required fields visibly but not by colour alone', () => {
    field({ required: true });
    expect(screen.getByText('*')).toBeInTheDocument();
    expect(screen.getByLabelText(/Email/)).toBeRequired();
  });

  it('without hint or error the control has no aria-describedby', () => {
```

```tsx
interface ControlProps {
  id: string;
  'aria-describedby'?: string;
  'aria-invalid'?: boolean;
  required?: boolean;
}

interface FormFieldProps {
  id: string;
  label: string;
  hint?: string;
  error?: string;
  required?: boolean;
  className?: string;
  children: (props: ControlProps) => ReactNode;
}

export function FormField({ id, label, hint, error, required, className, children }: FormFieldProps) {
  const uid = useId();
  const messageId = `${id}-${error ? 'error' : 'hint'}-${uid}`;
  const hasMessage = Boolean(error || hint);
  return (
    <div className={cn('flex flex-col gap-1.5', className)}>
      <Label htmlFor={id}>
        {label}
        {required ? <span aria-hidden="true" className="text-destructive"> *</span> : null}
      </Label>
      {children({
        id,
        'aria-describedby': hasMessage ? messageId : undefined,
        'aria-invalid': error ? true : undefined,
        required,
      })}
      {error ? (
        <p id={messageId} role="alert" className="text-xs text-destructive">
          {error}
        </p>
      ) : hint ? (
        <p id={messageId} className="text-xs text-muted-foreground">
          {hint}
        </p>
      ) : null}
    </div>
  );
}
```
