# Plan 10: Loading feedback, route skeletons, the Insight Orb and navigation speed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every click gets visible feedback within 100 ms (top progress bar + inline orb on the clicked item/button), every route shows a page-shaped skeleton instead of a frozen screen, the account page streams its tab content, and the server does each auth/accounts lookup once per request with a `Server-Timing` header to measure it.

**Architecture:** One CSS-only SVG loader (`InsightOrb`, keyframes in `styles/loading.css`) is the single visual for "working". A root-mounted `NavigationProgress` starts on internal link clicks (one capture-phase document listener) or an explicit `startProgress(href)` call (tabs, GET filter forms) and completes when `usePathname()`/`useSearchParams()` change, with a failsafe timeout. `NavLink` (Next's `useLinkStatus`) and `LoadingButton` give inline pending states. Every page segment gets a `loading.tsx` built from a small shared skeleton kit; the accounts list moves into a `(list)` route group so `/accounts/[id]` gets its own skeleton. Server side, `React.cache()` makes the owner check and the accounts/sync-status reads per-request singletons; the account page renders its header immediately and streams the tab inside `<Suspense>`; the layout streams the notification bell; the proxy emits `Server-Timing: auth;dur=…`.

**Tech Stack:** Next.js 16.4 App Router (`next/link` `useLinkStatus`, `next/form`, `loading.tsx`, Suspense streaming), React 19.3 (`cache`, `useId`), Tailwind 4 + un-layered CSS, next-intl 4, Vitest 5 + Testing Library + jsdom. **New dependencies: none.**

**Spec:** `docs/superpowers/specs/2026-10-15-creator-toolkit-design.md` §0, §1, §3 (this plan), §8 (cross-cutting rules). Project rules: `CLAUDE.md` (binding). Next 16 docs read for this plan (in `node_modules/next/dist/docs/01-app/`): `03-api-reference/04-functions/use-link-status.md`, `03-api-reference/03-file-conventions/loading.md`, `03-api-reference/03-file-conventions/layout.md` ("Interaction with loading.js"), `02-guides/prefetching.md`, `01-getting-started/06-fetching-data.md` ("Reusing data with React.cache"), `03-api-reference/02-components/form.md`.

## Decisions taken in this plan (owner: please confirm the ones marked ⚠)

- ⚠ **Accounts list moves to a route group** `app/(app)/accounts/(list)/page.tsx` (URL unchanged: `/accounts`). Reason (Next 16 prefetching docs): a dynamic route is prefetched "layout to first loading boundary". With `accounts/loading.tsx` next to the list page, that boundary also wraps `/accounts/[id]`, so opening an account would flash the accounts-LIST skeleton before the account skeleton. Inside `(list)/` the list's skeleton only wraps the list.
- ⚠ **Server actions do not drive the top bar.** The bar completes on a URL change; an action does not change the URL, so it would crawl until the failsafe. Actions get the inline orb on their own button instead (`LoadingButton`), and "Sync now" (up to 35 s) gets a visible status line with the orb. The bar runs for: link clicks, tab changes, GET filter forms, back/forward completes it.
- ⚠ **`Server-Timing` is emitted by the proxy only** (`auth;dur=…`, plus `total` for the proxy's own work). Server Components cannot set response headers and the page body streams after the headers are sent, so page data time is read as "Waiting for server response (TTFB)" minus the `auth` span (documented in `docs/RUNBOOK_PERF.md`). A per-page header would need Cache Components or a route-handler rewrite — not worth it for one owner.
- **Proxy auth is unchanged** (spec §3 point 4d asked to evaluate it). The proxy already skips `getUser()` for aal2 sessions, and nothing can be shared between the proxy and the render (different execution contexts; `React.cache` is per render). Caching across requests would weaken auth. No safe win → left as is.
- **Owner check:** `getOwnerContext = cache(loadOwnerContext)`; `requireOwner()` returns it. `getSessionInfo()` and `rpc('is_owner')` run in parallel (the RPC needs only the cookie session; `is_owner()` itself enforces 2FA in SQL), but the decisions are taken in the old order: signed-out → `/login`, 2FA owed → `/login/verify`, RPC error → throw, not owner → `/auth/signout`. A rejected promise is cached too, so a second call in the same request fails the same way (fail closed). Server actions keep calling `requireOwner()`; outside a render there is no React cache scope and it simply runs again.
- **What actually gets faster per navigation:** on a client navigation the `(app)` layout is not re-rendered, so the page's owner check is the only render-side one; it now costs one round trip (parallel) instead of two. On a hard load the layout and the page share one check (was two). The bell no longer blocks first paint. `accounts/[id]` shows header + tab bar as soon as the accounts list is back; prefs and accounts load in parallel on calendar/account pages.
- **Orb:** SVG + CSS keyframes only (no JS loop), colours only from `--chart-1..3`, `--surface`. Sizes `xs` 16 px (inside buttons/nav), `md` 40 px (route skeleton caption), `lg` 96 px (report preview, with three rotating captions done in CSS). `prefers-reduced-motion: reduce` → arcs and sparkline stop, the whole orb pulses opacity slowly. `decorative` mode (`aria-hidden`, no role) is used inside buttons/links whose own `aria-busy` already announces the state.
- **Skeleton kit:** `components/shared/Skeletons.tsx` (header, stat row, chart block, table, tabs, card grid, `RouteLoading` wrapper with `md` orb + "Reading your insights…"). The shadcn `Skeleton` keeps `animate-pulse` but only under `motion-safe:`.
- **Filters become client navigations:** the Posts filter form and the Calendar account picker are `next/form` `<Form action="">` (same GET URL semantics, still works without JS) instead of full page reloads.
- **Inline link feedback** is limited to the sidebar/rail/bottom tabs and the Overview → account links (spec "where easy"). Other links still get the top bar.

## Review Focus

1. **A navigation that never commits** (server error, aborted by a second click, a click the app prevents, a link to the page you are on, a GET form submitted unchanged): the top bar must not crawl forever → Task 5 "never stays stuck: an aborted or failed navigation ends at the failsafe", "startProgress to the current URL does nothing", "ignores a same page / hash / api / download link"; rapid double-click → Task 5 "rapid clicks: one bar, the failsafe restarts on each click, one completion"; back/forward → Task 5 "back/forward while idle changes the URL without showing a bar".
2. **The cached owner check leaking or failing open** (a second request, another visitor, a failed RPC followed by a retry, server actions): → Task 9 "a new request checks again and never sees the previous user", "fails closed for every caller of a failing request, and the failure does not leak into the next request", "outside a request scope (server actions) every call checks again", "React's real server build passes through outside a request", and "signed out / 2FA owed still redirects although the parallel owner RPC said true".
3. **Reduced motion and every theme × mode** (OS "reduce motion", Mono dark where `--primary` is white, Sunset dark): arcs, sparkline and bar crawl stop, only a slow pulse remains; only theme tokens → Task 2 "reduced motion: the CSS stops arcs, sparkline and the bar crawl, and leaves a slow pulse" and "uses theme tokens only"; the 4 × 2 visual matrix is a runbook step in Task 14 (`docs/RUNBOOK_PERF.md` §3).
4. **The wrong skeleton / layout shift on swap** (opening `/accounts/[id]` flashing the accounts LIST skeleton; a future route added without a skeleton): → Task 4 "no loading.tsx wraps another route page" and "<route> has a loading.tsx next to its page"; skeleton grids reuse the page's column classes (Task 3 "SkeletonGrid … with the page grid columns passed through").
5. **A tab query failing while the header is already on screen** (Supabase hiccup on the Posts tab): the error must reach `app/(app)/error.tsx`, not leave an endless skeleton → Task 11 "a failing tab query rejects inside the boundary, after the header rendered"; the bell island never throws (`loadNotifications` returns an empty bell) → Task 12 "the island loads the notifications and renders the bell with them".

Also covered in the owning tasks: modified clicks (Ctrl/⌘/Shift/middle) and `target="_blank"` (Task 5), a signed-out visitor whose parallel RPC fails gets `/login`, not the error page (Task 9), "Sync now" running 35 s (Task 7 status line), the bell skeleton keeps the header from jumping (Task 12).

**Files:**
- Create: `styles/loading.css`, `components/shared/InsightOrb.tsx`

**Interfaces:**
- Consumes: `loading.*`, `common.loading` (Task 1); `cn` (`lib/utils.ts`).
- Produces:
  - `type OrbSize = 'xs' | 'md' | 'lg'`
  - `InsightOrb(props: { size?: OrbSize; label?: string; decorative?: boolean; captions?: boolean; className?: string })` — default `size="md"`. Non-decorative: `<span role="status" aria-live="polite">` wrapping the svg, a `sr-only` label (`label ?? t('common.loading')`) and, with `captions`, three `aria-hidden` rotating captions. Decorative: only the `aria-hidden` `<svg>` (className goes on the svg). The svg always has `class="insight-orb size-…" data-size={size}`.
  - CSS classes for later tasks: `.nav-progress[data-state="loading"|"done"]` (Task 5), `.link-pending` and `.link-pending-hide` (Task 6).

Design notes: `viewBox 0 0 48 48`; halo circle r 17 (`--chart-1`, breathing), core r 12 with a radial gradient `--chart-2 → --chart-1 → --chart-3`, three arcs r 16 / 19.5 / 22.5 (`pathLength=100`, dash 28/18/10, 1.4 s / 2.2 s reverse / 3.4 s), a sparkline drawn in `--surface` (light on dark orbs, dark on light orbs in every theme). Rotation uses `transform-box: view-box; transform-origin: 24px 24px` so the arcs spin around the centre at every size. `useId()` output contains characters that are not valid in `url(#…)`, so it is reduced to `[a-zA-Z0-9]` and prefixed `orb-`. The stylesheet is un-layered like `styles/density.css`; no class here collides with a Tailwind utility.

```tsx
'use client';

// The thin top bar for client navigations (creator-toolkit design §3). It starts on a plain left click on an internal
// link (one capture-phase listener, so every <Link> is covered without wrapping it) or on startProgress(href) for
// router.push / GET forms, and completes when the URL (pathname or query) changes. A failsafe ends it if the
// navigation never commits (aborted, prevented, failed). Server actions do not change the URL, so they never start it.
import { useEffect, useRef, useState } from 'react';
import { usePathname, useSearchParams } from 'next/navigation';

export const PROGRESS_START_EVENT = 'in2sight:progress-start';
export const FAILSAFE_MS = 12_000;
export const FADE_MS = 400;

/** A same-origin page navigation that changes path or query (not a hash jump, not the same URL, not an API/download). */
export function isNavigation(href: string, here: { href: string; origin: string; pathname: string; search: string } = window.location): boolean {
  let url: URL;
  try {
    url = new URL(href, here.href);
  } catch {
    return false;
  }
  if (url.origin !== here.origin || url.pathname.startsWith('/api/')) return false;
  return url.pathname + url.search !== here.pathname + here.search;
}

/** Start the bar for a programmatic navigation. Ignored when `href` would not change the page. */
export function startProgress(href: string): void {
  if (isNavigation(href)) window.dispatchEvent(new Event(PROGRESS_START_EVENT));
}

/** The URL a GET form (next/form, action="") navigates to: same path, the form fields as the query. */
export function formHref(form: HTMLFormElement): string {
  const q = new URLSearchParams();
  new FormData(form).forEach((v, k) => q.append(k, typeof v === 'string' ? v : v.name));
  return `?${q}`;
}

function clickedLink(e: MouseEvent): string | null {
  if (e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey) return null; // new tab/window: no navigation here
  const a = e.target instanceof Element ? e.target.closest('a[href]') : null;
  if (!(a instanceof HTMLAnchorElement) || (a.target && a.target !== '_self') || a.hasAttribute('download')) return null;
  return a.href;
}

type State = 'idle' | 'loading' | 'done';

export function NavigationProgress() {
  const [state, setState] = useState<State>('idle');
  const url = `${usePathname()}?${useSearchParams()?.toString() ?? ''}`;
  const failsafe = useRef<ReturnType<typeof setTimeout>>(undefined);
  const [seen, setSeen] = useState(url);

  // URL changed (navigation committed, or back/forward): finish a running bar. Adjusting state during render is the
  // React-recommended way to react to a changed value without an extra effect pass.
  if (url !== seen) {
    setSeen(url);
    if (state === 'loading') setState('done');
  }

  useEffect(() => {
    const start = () => {
      clearTimeout(failsafe.current);
      setState('loading');
      failsafe.current = setTimeout(() => setState('done'), FAILSAFE_MS);
    };
    const onClick = (e: MouseEvent) => {
      const href = clickedLink(e);
      if (href && isNavigation(href)) start();
    };
    document.addEventListener('click', onClick, true);
    window.addEventListener(PROGRESS_START_EVENT, start);
    return () => {
      document.removeEventListener('click', onClick, true);
      window.removeEventListener(PROGRESS_START_EVENT, start);
      clearTimeout(failsafe.current);
    };
  }, []);

  useEffect(() => {
    if (state !== 'done') return;
    clearTimeout(failsafe.current);
    const t = setTimeout(() => setState('idle'), FADE_MS);
    return () => clearTimeout(t);
  }, [state]);

  return state === 'idle' ? null : <div aria-hidden="true" data-state={state} className="nav-progress" />;
}
```

'use client';

// A next/link that shows the xs orb while ITS navigation is pending (useLinkStatus must live inside the <Link>).
// With an icon the orb takes the icon's place; without one it sits just after the text. Both are absolutely positioned
// inside a fixed box, so nothing shifts; .link-pending / .link-pending-hide swap them only after 100 ms (fast navigations show nothing).
import type { ComponentProps, ReactNode } from 'react';
import Link, { useLinkStatus } from 'next/link';
import type { LucideIcon } from 'lucide-react';
import { InsightOrb } from '@/components/shared/InsightOrb';
import { cn } from '@/lib/utils';

function Pending({ icon: Icon, iconClassName, children }: { icon?: LucideIcon; iconClassName?: string; children: ReactNode }) {
  const { pending } = useLinkStatus();
  const orb = <InsightOrb size="xs" decorative className="link-pending absolute inset-0 m-auto" />;
  if (!Icon)
    return (
      <span className="relative">
        {children}
        {pending ? (
          <span className="absolute top-1/2 left-full ml-1 size-4 -translate-y-1/2">
            {orb}
          </span>
        ) : null}
      </span>
    );
  return (

```ts
import { cache } from 'react';
import { redirect } from 'next/navigation';
import { getSessionInfo } from '@/lib/auth/session';
import { createServerSupabase } from '@/lib/supabase/server';

export interface OwnerContext {
  userId: string;
  email: string | null;
}

/**
 * The owner check itself (uncached; exported for tests). The session lookup and the `is_owner` RPC run in parallel —
 * the RPC needs only the cookie session, and `is_owner()` enforces 2FA in SQL too — but the answers are applied in the
 * fail-closed order: signed out → /login, 2FA owed → /login/verify, RPC failure → throw, not the owner → /auth/signout.
 */
export async function loadOwnerContext(): Promise<OwnerContext> {
  const supabase = await createServerSupabase();
  // A failed check throws (error boundary): redirecting to /login would loop, the proxy bounces signed-in users back
  // to /overview. A definite "not the owner" signs the session out first. A rejected RPC becomes "failed", never "owner".
  const owner = supabase.rpc('is_owner').then(
    (r) => r,
    () => ({ data: null, error: true }),
  );
  const info = await getSessionInfo(supabase);
  if (!info.signedIn || !info.userId) redirect('/login');
  if (info.mfaRequired && info.aal !== 'aal2') redirect('/login/verify');
  const { data, error } = await owner;
  if (error) throw new Error('Owner check failed');
  if (data !== true) redirect('/auth/signout');
  return { userId: info.userId, email: info.email };
}

/**
 * One owner check per request: the (app) layout and the page share it. React.cache is scoped to the current server
 * request (no sharing between requests or users) and caches a rejection too, so every caller in a failing request
 * fails the same way. Outside a render (server actions) there is no cache scope and the check simply runs again.
 */
export const getOwnerContext = cache(loadOwnerContext);

/** Server guard for the (app) area: the proxy is the first gate, this is the second. */
export function requireOwner(): Promise<OwnerContext> {
  return getOwnerContext();
}
```
