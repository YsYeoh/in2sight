# Plan 12a: Time Scope — one shared range/compare/granularity filter instead of 7/30/90 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the fixed 7/30/90-day `PeriodSelect` with the shared **Time Scope** of the approved design (presets 7d/14d/30d/90d/6m/1y/YTD/all, custom date range, week/month/quarter pickers, compare to previous period / same period last year / custom days / nothing, granularity auto/day/week/month), kept in the URL and used by Overview, the account pages and their tabs, Calendar and the Excel/PDF exports — with owner-timezone, DST-safe days, null-safe bucketing, a data-coverage note, and reads that no longer silently stop at 200 days or PostgREST's 1000-row cap.

**Architecture:** A pure library `lib/time-scope/` turns the URL (`?from&to&cmp&gran`, plus picker shorthands and old `?period=` links) into a `TimeScope`, and a `TimeScope` + today + the first captured day into a `ResolvedScope` (KPI window, covered days, comparison days, effective granularity, coverage flags). Day maths stays on `'YYYY-MM-DD'` strings (`lib/sync/time.ts` `addDays`, never `Date` arithmetic across DST); the only day→instant conversion is `dayStart()` for `posted_at` bounds. `summarize()` in `lib/analysis/growth.ts` generalises from "period days" to a window (`{ last: n }` = the old rolling behaviour, or fixed days) with a comparison mode; `lib/analysis/buckets.ts` sums/levels daily rows into day/week/month buckets and marks partial ones. Loaders page through `.range()` (owner session, RLS) from the scope's first needed day. One client component, `TimeScopeBar`, renders presets as links, compare/granularity as GET-form selects and the pickers as GET forms inside a `ResponsiveDialog` — the URL is the only state, so the top progress bar and route skeletons keep working unchanged. Exports take the same parameters (strictly allow-listed) and put the range into file names and sheets.

**Tech Stack:** Next.js 16 App Router (server pages, client components), TypeScript strict, `@supabase/supabase-js` (owner session only), next-intl 4, shadcn/Radix (`Button`, `Dialog` via `ResponsiveDialog`), recharts 3 (unchanged), Vitest 5 + Testing Library + jsdom 29. **New dependencies: none** (a date library is not needed: day strings + `lib/sync/time.ts` + `Intl` already cover owner-timezone days and DST; native `<input type="date">` and `<select>` cover the pickers).

**Spec:** `docs/superpowers/specs/2026-10-15-creator-toolkit-design.md` §0b bullet "Drill-down & time scope (owner, 2026-10-16)" (approved design), §0b Round 3/4 (desktop-first, more than 4 accounts soon, own accounts only), §8 (cross-cutting rules); `docs/SPEC.md` §7 (metric definitions, "Delta"), §7b (Overview, "one date-range switch"), §7d (exports). Project rules: `CLAUDE.md` (binding).

## Decisions taken in this plan (owner: please confirm the ones marked ⚠)

- **Default = last 30 days vs the previous 30 days, automatic buckets** (spec/SPEC §7b say 30). The default scope serialises to NO parameters, so every existing bare link (`/overview`, `/accounts/<id>`) keeps meaning the same thing.
- **URL format** (compact, human-readable, bookmarkable; the spec's four keys): `from=7d|14d|30d|90d|6m|1y|ytd|all` for a preset, `from=YYYY-MM-DD&to=YYYY-MM-DD` for fixed days, `cmp=none|yoy` (previous period is the default), `cfrom=…&cto=…` for custom comparison days, `gran=day|week|month` (auto is the default). Picker forms submit shorthands that are accepted as input only: `week=<any day of that week>`, `month=YYYY-MM`, `quarter=YYYY-Qn`; old `period=7|30|90` links map to the matching preset. Links the app builds always use the canonical form. Why: a preset stays rolling when bookmarked ("last 30 days" next month is still the last 30 days), fixed days stay fixed, and the plain GET-form shorthands make the pickers work without client-side date code.
- **Rolling presets keep today's exact behaviour:** 7d/14d/30d/90d/6m (= 182 days, 26 weeks)/1y (= 365 days) measure the last N days ending on the account's latest settled day (Instagram's up-to-48 h lag, `MAX_LAG_DAYS`), compared with the N days before. All existing 7/30/90 tests stay green unchanged.
- **Fixed ranges** (custom days, week, month, quarter, YTD, all) measure their days up to the latest settled day, so a running month (1–17 Oct) is never compared as if it were complete.
- **"Previous period"** = the same calendar unit before for whole months (a month → the previous month, a quarter → the previous quarter, Jan–Dec → the previous year), otherwise the same number of days immediately before (a week → the previous week). **"Same period last year"** = the same days one year earlier (29 Feb → 28 Feb; a month end stays a month end). Every comparison window is cut to the current window's length from its start, so 1–15 Oct compares with 1–15 Sep (never with all of September) and the existing "comparable only at ≥ 80 % coverage" rule applies to any comparison unchanged.
- **Comparison partly outside coverage:** no new rule. The comparison is shown only when its window has ≥ 80 % of days with data (the existing `MIN_COVERAGE`; while importing it must be complete); otherwise the KPI shows its value with "Not enough history to compare yet". The scope bar adds one sentence when the range or the comparison starts before the first captured day ("data from …").
- **`all` = from the first captured day to today, capped at `MAX_DAYS` = 1,830 days (≈ 5 years); it is never compared** (there is no earlier period). The same cap bounds every custom range (a longer one keeps its end), so the largest daily read is ≈ 2,200 rows per account (two 1,000-row pages plus a short one).
- **Auto granularity:** day up to 92 days, week up to 400 days (so 6 months and 1 year chart weekly), month above. A manual choice always wins. Weeks start on the owner's week-start preference; a bucket the range starts or ends inside is marked partial (`*` on its label, explained under the chart). Sums (reach, views) add the days that have data and stay `null` (never 0) when none does; followers take the last value in the bucket.
- **Scope across pages:** the URL is the only state. Links that already exist carry the current scope: account tabs (they used to DROP `?period`), Overview account cards → account page, account "back" → Overview, account → Calendar, the Posts filter form, the export dialog, and the main navigation's Overview and Calendar items (AppShell reads the current URL with `useSearchParams` and appends only the scope keys). Pages without dates (Accounts list, Tags, Settings) get plain links.
- ⚠ **Posts and Stories tabs follow the scope.** Default 30 days: the Posts tab used to list every stored post (newest 500) and the Stories tab the last 14 days. "All" restores the long list. The post count line keeps saying "Showing X of Y posts".
- ⚠ **Calendar without scope parameters still opens on the current month** (its old default); with a scope it shows the scope's days as whole weeks (days outside the scope dimmed) and its arrows step one period (a month steps by months). Old `?month=YYYY-MM` links keep working (they are the month picker's shorthand).
- **Format comparison follows the scope** (posts published in the range); the best-time heatmaps stay on all stored posts and the last 30 days of followers-online (they need sample size, and Instagram keeps only 30 days of online followers). The Audience tab shows the latest snapshot and hides the scope bar.
- **Flags stay "right now" signals:** reach drop is always last 7 vs previous 7 days (alert rule); "taking off" uses the rolling preset's days (as before) and 7 days for fixed ranges.
- **Reads:** `loadDaily` pages through `.range()` from `readFrom(scope)` to today (oldest first); post reads go newest first until they have both the newest 500 (flags and heatmaps need them) and every post back to the scope's first day; Calendar media reads page up to 5,000 items and keep the existing "too many items" notice; all reads stay on the OWNER SESSION client under RLS. `DAILY_LIMIT` is removed.
- ⚠ **Stories keep a cap of 200 per account per range** (`STORY_LIMIT`; each Story carries up to ~48 snapshots, so a year of Stories would be several MB). The Stories tab now SAYS when it is capped ("Showing the newest 200 Stories in this range"); the export's Stories sheet has the same cap. A per-Story "final numbers" rollup in Plan 12b removes it.
- **Exports use the page's scope:** the dialog shows the scope it will export (changed with the bar), the request carries the canonical scope parameters, the server allow-lists them strictly (`bad_params` for junk, repeated keys or shorthands; old `period=7|30|90` still accepted; no range parameter = the default 30 days), file names become `in2sight-<scope>-<from>_<to>.<ext>`, the Summary sheet gains "Compared from/to" columns, and the PDF report states both windows.
- **No SQL migration.** Paged reads over the existing tables are enough for 12a; rollups belong to Plan 12b.
- **New dependencies: none.**

**Files:**

**Interfaces:**
- Consumes: `addDays(day, n)` (`lib/sync/time.ts`), `weekdayOf(day)` (`lib/analysis/best-time.ts`, 0 = Sunday), `WeekStart` (`lib/prefs.ts`).
- Produces:
  - `interface DayRange { from: string; to: string }` (inclusive owner-timezone days)
  - `type Window = { last: number } | DayRange` (rolling N days up to the latest settled day, or fixed days)
  - `type Compare = 'none' | 'prev' | 'yoy' | DayRange`, `type Granularity = 'day' | 'week' | 'month'`
  - `isDay(v: unknown): v is string` (real day, years 2000–2099), `daysBetween(a, b): number`, `daysIn(r): number`, `minDay(a, b): string`, `addMonths(day, n): string`
  - `weekOf(day, weekStart): DayRange`, `monthOf(day): DayRange`, `quarterOf(day): DayRange`, `wholeMonths(r): number`
  - `stepRange(r, dir: 1 | -1, byMonths = true): DayRange`, `lastYear(r): DayRange`, `compareRange(asked: Window, cur: DayRange, cmp: Compare): DayRange | null`
  - `autoGranularity(days): Granularity`, `bucketStart(day, gran, weekStart): string`, `bucketRange(start, gran): DayRange`

All day maths is on `'YYYY-MM-DD'` strings (`Date.UTC` only to read a calendar, never an instant), so DST cannot shift a day.

// Calendar arithmetic on owner-timezone days ('YYYY-MM-DD' strings, exactly what the sync writes). Pure and
// timezone-free: a day string has no clock, so DST can never shift it. The ONLY place a day becomes an instant is
// dayStart() in lib/sync/time.ts (used by the loaders for posted_at bounds).
import { weekdayOf } from '@/lib/analysis/best-time';
import type { WeekStart } from '@/lib/prefs';
import { addDays } from '@/lib/sync/time';

/** Inclusive owner-timezone days. */
export interface DayRange {
  from: string;
  to: string;
}

/** A KPI window: the last `last` days up to the account's latest settled day (rolling presets), or fixed days. */
export type Window = { last: number } | DayRange;
/** What the current window is compared with: nothing, the previous period, the same period a year earlier, or fixed days. */
export type Compare = 'none' | 'prev' | 'yoy' | DayRange;
export type Granularity = 'day' | 'week' | 'month';

const pad = (n: number) => String(n).padStart(2, '0');
const DAY = /^20\d\d-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$/;

/** A real calendar day of the years 2000-2099 ('2026-02-30' does not round-trip and is rejected). */
export function isDay(v: unknown): v is string {
  return typeof v === 'string' && DAY.test(v) && new Date(`${v}T00:00:00Z`).toISOString().slice(0, 10) === v;
}

/** b − a in days. */
export const daysBetween = (a: string, b: string): number => Math.round((Date.parse(`${b}T00:00:00Z`) - Date.parse(`${a}T00:00:00Z`)) / 86_400_000);
export const daysIn = (r: DayRange): number => daysBetween(r.from, r.to) + 1;
export const minDay = (a: string, b: string): string => (a < b ? a : b);

const lastOfMonth = (y: number, m: number) => new Date(Date.UTC(y, m, 0)).getUTCDate(); // m is 1-based
const monthEnd = (day: string) => `${day.slice(0, 8)}${pad(lastOfMonth(Number(day.slice(0, 4)), Number(day.slice(5, 7))))}`;

/** Month arithmetic that keeps the day of the month where it can (31 Mar − 1 month = 28/29 Feb). */
export function addMonths(day: string, n: number): string {
  const i = Number(day.slice(0, 4)) * 12 + Number(day.slice(5, 7)) - 1 + n;
  const y = Math.floor(i / 12);
  const m = (i % 12) + 1;
  return `${y}-${pad(m)}-${pad(Math.min(Number(day.slice(8)), lastOfMonth(y, m)))}`;
}

export function weekOf(day: string, weekStart: WeekStart): DayRange {
  const from = addDays(day, -((weekdayOf(day) - (weekStart === 'sun' ? 0 : 1) + 7) % 7));
  return { from, to: addDays(from, 6) };
}

export function monthOf(day: string): DayRange {
  return { from: `${day.slice(0, 8)}01`, to: monthEnd(day) };
}

export function quarterOf(day: string): DayRange {
  const first = (Math.floor((Number(day.slice(5, 7)) - 1) / 3) * 3) + 1;
  const from = `${day.slice(0, 5)}${pad(first)}-01`;
  return { from, to: monthEnd(addMonths(from, 2)) };
}

/** How many whole calendar months the range spans (1 = a month, 3 = a quarter, 12 = a year), 0 when it is not whole months. */
export function wholeMonths(r: DayRange): number {
  if (!r.from.endsWith('-01') || r.to !== monthEnd(r.to) || r.to < r.from) return 0;
  return (Number(r.to.slice(0, 4)) - Number(r.from.slice(0, 4))) * 12 + Number(r.to.slice(5, 7)) - Number(r.from.slice(5, 7)) + 1;
}

/**
 * The range one step back (dir −1) or forward (+1). Whole months move by whole months (September → August, Q3 →
 * Q2, a year → the year before); anything else moves by its own length in days. `byMonths: false` always moves by days.
 */
export function stepRange(r: DayRange, dir: 1 | -1, byMonths = true): DayRange {
  const k = byMonths ? wholeMonths(r) : 0;
  if (k) return { from: addMonths(r.from, dir * k), to: monthEnd(addMonths(`${r.to.slice(0, 8)}01`, dir * k)) };
  const n = daysIn(r);
  return { from: addDays(r.from, dir * n), to: addDays(r.to, dir * n) };
}

/** The same days a year earlier (29 Feb → 28 Feb); a month end stays a month end. */
export function lastYear(r: DayRange): DayRange {
  return { from: addMonths(r.from, -12), to: r.to === monthEnd(r.to) ? monthEnd(addMonths(r.to, -12)) : addMonths(r.to, -12) };
}

/**
 * The comparison days for the current window `cur` (the days really measured). `asked` is what the URL asked for: a
 * fixed range keeps its calendar meaning (October compares with September, aligned from the 1st), a rolling window
 * moves by days. The result is cut to the current window's length from its start, so a month that is still running
 * (1–15 Oct) compares with the same days of the previous month (1–15 Sep), never with a whole month.
 */
export function compareRange(asked: Window, cur: DayRange, cmp: Compare): DayRange | null {
  if (cmp === 'none') return null;
  const rolling = 'last' in asked;
  const base = rolling ? cur : asked;
  const full = typeof cmp === 'object' ? cmp : cmp === 'prev' ? stepRange(base, -1, !rolling) : lastYear(base);
  const end = addDays(full.from, daysIn(cur) - 1);
  return { from: full.from, to: minDay(full.to, end) };
}

/** Chart buckets for a range length when the owner did not pick one: days up to ~3 months, weeks up to ~13 months, then months. */
export function autoGranularity(days: number): Granularity {
  return days <= 92 ? 'day' : days <= 400 ? 'week' : 'month';
}

/** First day of the bucket a day falls in. */
export function bucketStart(day: string, gran: Granularity, weekStart: WeekStart): string {
  return gran === 'day' ? day : gran === 'week' ? weekOf(day, weekStart).from : `${day.slice(0, 8)}01`;
}

/** All days of a bucket that starts on `start`. */
export function bucketRange(start: string, gran: Granularity): DayRange {
  return gran === 'day' ? { from: start, to: start } : gran === 'week' ? { from: start, to: addDays(start, 6) } : monthOf(start);
}

// The Time Scope (creator-toolkit spec §0b): ONE URL state `?from&to&cmp&gran` shared by Overview, the account
// pages, Calendar and exports. Everything here is pure: parse never throws (hostile or malformed values fall back
// to the default), "today" is an input, days are owner-timezone 'YYYY-MM-DD' strings.
//
// URL format (canonical, defaults omitted so the default scope is a bare path):
//   from=7d|14d|30d|90d|6m|1y|ytd|all            a preset (rolling: it moves with today)
//   from=2026-09-01&to=2026-09-30                fixed days (a month, a quarter, a week or any custom range)
//   cmp=none|yoy  (default: previous period)     cfrom=…&cto=…  custom comparison days
//   gran=day|week|month (default: auto)
// Accepted as input only (pickers and old links): week=<any day of it>, month=YYYY-MM, quarter=YYYY-Qn, period=7|30|90.
import { MAX_LAG_DAYS } from '@/lib/analysis/growth';
import type { WeekStart } from '@/lib/prefs';
import { addDays } from '@/lib/sync/time';
import { autoGranularity, compareRange, daysIn, isDay, minDay, monthOf, quarterOf, stepRange, weekOf, type Compare, type DayRange, type Granularity, type Window } from '@/lib/time-scope/range';

export const PRESETS = ['7d', '14d', '30d', '90d', '6m', '1y', 'ytd', 'all'] as const;
export type Preset = (typeof PRESETS)[number];
/** Rolling presets = the last N days up to the latest settled day (6 months = 26 weeks). */
export const ROLLING: Partial<Record<Preset, number>> = { '7d': 7, '14d': 14, '30d': 30, '90d': 90, '6m': 182, '1y': 365 };
export const DEFAULT_PRESET: Preset = '30d'; // SPEC §7b default
/** The longest range anyone can ask for (about 5 years); it also bounds "all" and every read. */
export const MAX_DAYS = 1830;
export const GRANULARITIES = ['auto', 'day', 'week', 'month'] as const;
export type GranChoice = (typeof GRANULARITIES)[number];
/** URL keys owned by the scope: a link or form that sets a scope drops all of them first. */
export const SCOPE_KEYS = ['from', 'to', 'cmp', 'cfrom', 'cto', 'gran', 'week', 'month', 'quarter', 'period'] as const;

export interface TimeScope {
  range: Preset | DayRange;
  cmp: Compare;
  gran: GranChoice;
}

export const DEFAULT_SCOPE: TimeScope = { range: DEFAULT_PRESET, cmp: 'prev', gran: 'auto' };

type Params = Record<string, string | string[] | undefined> | URLSearchParams;
const pad = (n: number) => String(n).padStart(2, '0');

/** One value per key: a repeated key (?from=a&from=b) is ambiguous and counts as missing. */
function one(sp: Params, key: string): string | null {
  if (sp instanceof URLSearchParams) {
    const all = sp.getAll(key);
    return all.length === 1 ? all[0] : null;
  }
  const v = sp[key];
  return typeof v === 'string' ? v : null;
}

/** Days in order, at most MAX_DAYS long (a longer range keeps its end and loses its start). */
function ordered(a: string, b: string): DayRange {
  const [from, to] = a <= b ? [a, b] : [b, a];
  return daysIn({ from, to }) > MAX_DAYS ? { from: addDays(to, -(MAX_DAYS - 1)), to } : { from, to };
}

function parseRange(sp: Params, weekStart: WeekStart): Preset | DayRange {
  const from = one(sp, 'from');
  const to = one(sp, 'to');
  if ((PRESETS as readonly (string | null)[]).includes(from)) return from as Preset;
  if (isDay(from) && isDay(to)) return ordered(from, to);
  const week = one(sp, 'week');
  if (isDay(week)) return weekOf(week, weekStart);
  const month = one(sp, 'month')?.match(/^(20\d\d)-(0[1-9]|1[0-2])$/);
  if (month) return monthOf(`${month[0]}-01`);
  const quarter = one(sp, 'quarter')?.match(/^(20\d\d)-Q([1-4])$/);
  if (quarter) return quarterOf(`${quarter[1]}-${pad((Number(quarter[2]) - 1) * 3 + 1)}-01`);
  const period = one(sp, 'period'); // links from before the Time Scope
  return period === '7' || period === '30' || period === '90' ? (`${period}d` as Preset) : DEFAULT_PRESET;
}

/** The scope in a URL. Never throws: anything unknown, repeated or malformed falls back to the default part. */
export function parseTimeScope(sp: Params, weekStart: WeekStart = 'mon'): TimeScope {
  const range = parseRange(sp, weekStart);
  const cfrom = one(sp, 'cfrom');
  const cto = one(sp, 'cto');
  const c = one(sp, 'cmp');
  const cmp: Compare = isDay(cfrom) && isDay(cto) ? ordered(cfrom, cto) : c === 'none' || c === 'yoy' ? c : 'prev';
  const g = one(sp, 'gran');
  return {
    range,
    cmp: range === 'all' ? 'none' : cmp, // "everything" has no earlier period to compare with
    gran: (GRANULARITIES as readonly (string | null)[]).includes(g) ? (g as GranChoice) : 'auto',
  };
}

/** Canonical URL parameters of a scope; default parts are left out (the default scope is {}). */
export function scopeParams(s: TimeScope): Record<string, string> {
  const p: Record<string, string> = {};
  if (typeof s.range === 'object') Object.assign(p, { from: s.range.from, to: s.range.to });
  else if (s.range !== DEFAULT_PRESET) p.from = s.range;
  if (typeof s.cmp === 'object') Object.assign(p, { cfrom: s.cmp.from, cto: s.cmp.to });
  else if (s.cmp !== 'prev' && s.range !== 'all') p.cmp = s.cmp;
  if (s.gran !== 'auto') p.gran = s.gran;
  return p;
}

export const scopeQuery = (s: TimeScope): string => new URLSearchParams(scopeParams(s)).toString();

/** A relative link ('?…') that shows scope `s` and keeps the page's own parameters (tab, filters, account). */
export function scopeHref(s: TimeScope, keep: Record<string, string> = {}): string {
  const q = new URLSearchParams(keep);
  for (const k of SCOPE_KEYS) q.delete(k);
  for (const [k, v] of Object.entries(scopeParams(s))) q.set(k, v);
  return `?${q}`;
}

/** Only the scope parameters of a URL (for links into other scoped pages): '' when there are none. */
export function scopeQueryOf(search: URLSearchParams): string {
  const q = new URLSearchParams();
  for (const k of SCOPE_KEYS) for (const v of search.getAll(k)) q.append(k, v);
  return q.toString();
}

export interface ResolvedScope {
  scope: TimeScope; // what is shown (a range that starts after today has fallen back to the default)
  params: Record<string, string>; // scopeParams(scope), for hidden form fields
  query: string; // scopeQuery(scope), '' for the default; appended to internal links
  preset: Preset | null;
  window: Window; // what the KPIs measure (summarize)
  range: DayRange; // the covered days up to today: posts, Stories, calendar, labels
  compare: DayRange | null; // comparison days for labels (each account's KPIs cut their own, see compareRange)
  gran: Granularity; // chart buckets (auto resolved)
  earliest: string | null; // first captured day among the loaded rows; null when nothing was captured
  partial: boolean; // part of the range is before the first captured day
  comparePartial: boolean; // part of the comparison is before the first captured day
}

function windowOf(r: Preset | DayRange, today: string, earliest: string | null): Window {
  if (typeof r === 'object') return r;
  const days = ROLLING[r];
  if (days) return { last: days };
  if (r === 'ytd') return { from: `${today.slice(0, 4)}-01-01`, to: today };
  const floor = addDays(today, -(MAX_DAYS - 1)); // 'all': from the first captured day, at most MAX_DAYS back
  return { from: earliest === null ? today : earliest < floor ? floor : minDay(earliest, today), to: today };
}

/** Turns the URL state into concrete days. `earliest` = first captured day (see earliestDay), needed by "all". */
export function resolveScope(s: TimeScope, today: string, earliest: string | null = null): ResolvedScope {
  const scope: TimeScope = typeof s.range === 'object' && s.range.from > today ? { ...s, range: DEFAULT_PRESET } : s;
  const r = scope.range;
  const window = windowOf(r, today, earliest);
  const range = 'last' in window ? { from: addDays(today, -(window.last - 1)), to: today } : { from: window.from, to: minDay(window.to, today) };
  const compare = compareRange(window, range, scope.cmp);
  return {
    scope,
    params: scopeParams(scope),
    query: scopeQuery(scope),
    preset: typeof r === 'string' ? r : null,
    window,
    range,
    compare,
    gran: scope.gran === 'auto' ? autoGranularity(daysIn(range)) : scope.gran,
    earliest,
    partial: earliest === null || range.from < earliest,
    comparePartial: compare !== null && (earliest === null || compare.from < earliest),
  };
}

/** First day the loaders read: both windows plus Instagram's lag, and at least the 2 × 7 days the reach-drop flag needs. */
export function readFrom(s: TimeScope, today: string): string {
  if (s.range === 'all') return addDays(today, -(MAX_DAYS - 1));
  const r = resolveScope(s, today);
  const first = minDay(r.range.from, r.compare?.from ?? r.range.from);
  return minDay(addDays(first, -(1 + MAX_LAG_DAYS)), addDays(today, -(2 * 7 + 1 + MAX_LAG_DAYS)));
}

/** The first captured day across accounts (each list oldest first, as the loaders return it). */
export function earliestDay(lists: { day: string }[][]): string | null {
  return lists.reduce<string | null>((m, l) => (l.length && (m === null || l[0].day < m) ? l[0].day : m), null);
}

/** The same scope one period back or forward (Calendar arrows); null when it would start after today. */
export function stepScope(r: ResolvedScope, dir: 1 | -1, today: string): TimeScope | null {
  const rolling = 'last' in r.window;
  const next = stepRange(rolling ? r.range : (r.window as DayRange), dir, !rolling);
  return next.from > today ? null : { ...r.scope, range: next };
}

// Daily rows → day / week / month buckets for charts (Time Scope granularity). Pure.
// Sums add only the days that have a value and stay null (never 0) when none has one; levels such as followers take
// the bucket's last value. A bucket that the rows start or end inside (the range cuts it) is listed in `partial`.
import type { WeekStart } from '@/lib/prefs';
import { bucketRange, bucketStart, type Granularity } from '@/lib/time-scope/range';

export type Agg = 'sum' | 'last';
export type DayValues<K extends string> = { day: string } & Record<K, number | null>;

/** `rows` must be consecutive days, oldest first (as summarize() builds them). Output rows are keyed by the bucket's first day. */
export function bucketize<K extends string>(rows: DayValues<NoInfer<K>>[], gran: Granularity, weekStart: WeekStart, aggs: Record<K, Agg>): { rows: DayValues<K>[]; partial: string[] } {
  if (rows.length === 0) return { rows: [], partial: [] };
  const keys = Object.keys(aggs) as K[];
  const buckets = new Map<string, Record<string, number | null>>();
  for (const r of rows) {
    const day = bucketStart(r.day, gran, weekStart);
    const b = buckets.get(day) ?? Object.fromEntries(keys.map((k) => [k, null]));
    for (const k of keys) {
      const v = r[k];
      if (typeof v === 'number' && Number.isFinite(v)) b[k] = aggs[k] === 'sum' ? (b[k] ?? 0) + v : v;
    }
    buckets.set(day, b);
  }
  const first = rows[0].day;
  const last = rows[rows.length - 1].day;
  return {
    rows: [...buckets].map(([day, b]) => ({ ...b, day }) as DayValues<K>),
    partial: [...buckets.keys()].filter((day) => {
      const span = bucketRange(day, gran);
      return span.from < first || span.to > last;
    }),
  };
}

// Account growth over a window vs a comparison window (SPEC §7 "Delta"; Time Scope: the previous period, the same
// period last year, custom days or none). Pure and deterministic: "today" and the timezone are inputs, never the clock.
import { addDays, localDay } from '@/lib/sync/time';
import type { DailyRow, MissingReason, Post } from '@/lib/analysis/types';
import { compareRange, daysBetween, daysIn, minDay, type Compare, type DayRange, type Window } from '@/lib/time-scope/range';

export interface Totals {
  followers: number | null; // latest snapshot (current) / snapshot one period earlier (prior)
  reach: number | null;
  views: number | null;
  interactions: number | null;
  netFollows: number | null; // Σ(follows − unfollows); null when Instagram gave no follow data (under 100 followers)
  rate: { interactions: number; reach: number } | null; // engagement-rate parts; null unless the account has both
  posts: number; // feed posts + reels published in the window (stories excluded)
  days: number; // days in the window that have reach data (coverage)
}

export interface Summary {
  period: number; // days in the current window
  from: string; // first day of the current window
  endDay: string; // last day of the current window
  compare: DayRange | null; // the comparison window; null = no comparison asked for
  current: Totals;
  prior: Totals; // totals over `compare` (empty when there is none)
  coverage: { current: number; prior: number }; // share of each window's days that have reach data (0–1)
  reachByDay: { day: string; value: number | null }[]; // current window, oldest first
}

export type KpiId = 'followers' | 'reach' | 'views' | 'engagementRate' | 'posts' | 'netFollows';

export interface Kpi {
  value: number | null;
  prior: number | null;
  diff: number | null; // value − prior (for engagement rate: percentage points as a ratio, 0.004 = +0.4 pp)
  change: number | null; // relative change (diff / prior); null when prior is 0 or missing
  reason: MissingReason | null; // why value or the comparison is missing
}

/** Instagram lags up to 48 h; a latest reach day older than yesterday − this means the account stopped syncing. */
export const MAX_LAG_DAYS = 3;

/** A window only counts for a comparison when at least 80% of its days have data (sync gaps, Meta's 48 h lag). */
export const MIN_COVERAGE = 0.8;

const sum = (vals: (number | null)[]): number | null => {
  const nums = vals.filter((v): v is number => typeof v === 'number' && Number.isFinite(v));
  return nums.length ? nums.reduce((a, b) => a + b, 0) : null;
};

function totals(rows: DailyRow[], posts: Post[], from: string, to: string, tz: string): Omit<Totals, 'followers'> {
  const inWin = rows.filter((r) => r.day >= from && r.day <= to);
  const follow = inWin.filter((r) => r.follows !== null && r.unfollows !== null);
  const reach = sum(inWin.map((r) => r.reach));
  const interactions = sum(inWin.map((r) => r.interactions));
  return {
    reach,
    views: sum(inWin.map((r) => r.views)),
    interactions,
    rate: reach !== null && interactions !== null ? { interactions, reach } : null,
    netFollows: follow.length ? follow.reduce((a, r) => a + (r.follows as number) - (r.unfollows as number), 0) : null,
    posts: posts.filter((p) => {
      if (p.mediaType === 'STORY') return false;
      const d = localDay(new Date(p.postedAt), tz);
      return d >= from && d <= to;
    }).length,
    days: inWin.filter((r) => r.reach !== null).length,
  };
}

/** Last non-null followers value on or before `day`, with the day it was taken. */
function followersAt(sorted: DailyRow[], day: string): { day: string; value: number } | null {
  for (let i = sorted.length - 1; i >= 0; i--) {
    const r = sorted[i];
    if (r.day <= day && r.followers !== null) return { day: r.day, value: r.followers };
  }
  return null;
}

const NONE: Totals = { followers: null, reach: null, views: null, interactions: null, netFollows: null, rate: null, posts: 0, days: 0 };

/**
 * The "settled" day is the latest day with reach data before today (Instagram lags up to 48 h, so ending on
 * "yesterday" would compare a short window with a full one); with no data at all, or none within MAX_LAG_DAYS of
 * yesterday, it is yesterday. A rolling window (`{ last: n }`, or a plain number) is the n days ending on the settled
 * day; a fixed window keeps its first day and ends on its last day or the settled day, whichever comes first. The
 * comparison window comes from compareRange (same length, aligned on its start).
 * Followers are a daily snapshot written on the day they were read (can be today), so they use their own latest day:
 * today for a rolling window, the window's last day (at most today) for a fixed one.
 */
export function summarize(rows: DailyRow[], posts: Post[], window: number | Window, today: string, tz: string, cmp: Compare = 'prev'): Summary {
  const w: Window = typeof window === 'number' ? { last: window } : window;
  const sorted = [...rows].sort((a, b) => (a.day < b.day ? -1 : a.day > b.day ? 1 : 0));
  const yesterday = addDays(today, -1);
  const withReach = sorted.filter((r) => r.reach !== null && r.day <= yesterday);
  const latest = withReach.length ? withReach[withReach.length - 1].day : null;
  // a stale account (last reach day older than the lag allows) ends at yesterday, so its missing days count as gaps
  const settled = latest !== null && latest >= addDays(yesterday, -MAX_LAG_DAYS) ? latest : yesterday;
  const endDay = 'last' in w ? settled : minDay(w.to, settled > w.from ? settled : w.from);
  const from = 'last' in w ? addDays(endDay, -(w.last - 1)) : w.from;
  const period = daysIn({ from, to: endDay });
  const compare = compareRange(w, { from, to: endDay }, cmp);
  const curF = followersAt(sorted, 'last' in w ? today : minDay(w.to, today));
  // the comparison's follower snapshot sits as far before the current one as the comparison window ends before this one
  const priorF = curF && compare ? followersAt(sorted, addDays(curF.day, -daysBetween(compare.to, endDay))) : null;
  const byDay = new Map(sorted.map((r) => [r.day, r.reach]));
  const current: Totals = { followers: curF?.value ?? null, ...totals(sorted, posts, from, endDay, tz) };
  const prior: Totals = compare ? { followers: priorF?.value ?? null, ...totals(sorted, posts, compare.from, compare.to, tz) } : NONE;
  return {
    period,
    from,
    endDay,
    compare,
    current,
    prior,
    coverage: { current: current.days / period, prior: compare ? prior.days / daysIn(compare) : 0 },
    reachByDay: Array.from({ length: period }, (_, i) => {
      const day = addDays(from, i);
      return { day, value: byDay.get(day) ?? null };
    }),
  };
}

const add = (a: number | null, b: number | null) => (a === null ? b : b === null ? a : a + b);

type SumField = 'followers' | 'reach' | 'views' | 'interactions' | 'netFollows';
const SUM_FIELDS: SumField[] = ['followers', 'reach', 'views', 'interactions', 'netFollows'];

/**
 * Totals of several accounts. Comparability rule, per field: if any account contributes a current value but has NO
 * prior value (a newly connected account has no follower history), the combined prior is null, so the comparison is
 * "not enough history" instead of the new account's whole value showing up as growth. Accounts without a current
 * value contribute to neither side. Engagement rate sums interactions and reach over accounts that have both, so an
 * account with reach but no interactions never understates the rate.
 */
function combineTotals(cur: Totals[], pri: Totals[]): { current: Totals; prior: Totals } {
  const current = { posts: cur.reduce((n, t) => n + t.posts, 0), days: Math.min(...cur.map((t) => t.days)) } as Totals;
  const prior = { posts: pri.reduce((n, t) => n + t.posts, 0), days: Math.min(...pri.map((t) => t.days)) } as Totals;
  for (const f of SUM_FIELDS) {
    const who = cur.map((t, i) => (t[f] !== null ? i : -1)).filter((i) => i >= 0);
    current[f] = sum(who.map((i) => cur[i][f]));
    prior[f] = who.every((i) => pri[i][f] !== null) ? sum(who.map((i) => pri[i][f])) : null;
  }
  const who = cur.map((t, i) => (t.rate ? i : -1)).filter((i) => i >= 0);
  const rate = (list: Totals[]) => (who.every((i) => list[i].rate) && who.length ? who.reduce((a, i) => ({ interactions: a.interactions + list[i].rate!.interactions, reach: a.reach + list[i].rate!.reach }), { interactions: 0, reach: 0 }) : null);
  current.rate = rate(cur);
  prior.rate = rate(pri);
  return { current, prior };
}

/**
 * Sums several accounts' summaries (group or all-accounts totals). Each account keeps its own window end, so the
 * daily series is merged by position (day 1 … day N of each window) and labelled with the latest day at that
 * position. A fixed window starts on the same day for everyone and only its end can differ (each account's settled
 * day), so the longest window gives the length and position = calendar day there.
 * ponytail: positional merge; switch to calendar-day merge if accounts' lags ever differ by more than a day.
 */
export function combine(list: Summary[]): Summary | null {
  if (list.length === 0) return null;
  const { current, prior } = combineTotals(list.map((s) => s.current), list.map((s) => s.prior));
  const longest = list.reduce((a, s) => (s.period > a.period ? s : a));
  const reachByDay = longest.reachByDay.map((d0, i) => ({
    day: list.reduce((d, s) => (s.reachByDay[i] && s.reachByDay[i].day > d ? s.reachByDay[i].day : d), d0.day),
    value: list.reduce<number | null>((v, s) => add(v, s.reachByDay[i]?.value ?? null), null),
  }));
  return {
    period: longest.period,
    from: reachByDay[0]?.day ?? longest.from,
    endDay: list.reduce((d, s) => (s.endDay > d ? s.endDay : d), list[0].endDay),
    compare: longest.compare,
    current,
    prior,
    coverage: { current: current.days / longest.period, prior: longest.compare ? prior.days / daysIn(longest.compare) : 0 },
    reachByDay,
  };
}

const er = (t: Totals) => (t.rate && t.rate.reach > 0 ? t.rate.interactions / t.rate.reach : null);

function kpi(value: number | null, prior: number | null, comparable: boolean, emptyReason: MissingReason, shortReason: MissingReason | null = 'not_enough_history'): Kpi {
  if (value === null) return { value: null, prior, diff: null, change: null, reason: emptyReason };
  if (!comparable || prior === null) return { value, prior: null, diff: null, change: null, reason: shortReason };
  const diff = value - prior;
  return { value, prior, diff, change: prior === 0 ? (diff === 0 ? 0 : null) : diff / Math.abs(prior), reason: null };
}

/**
 * Headline numbers with their comparison. Never NaN or Infinity: a missing or zero base gives null + a reason.
 * backfilling (history still importing): a window with gaps says "Importing history…" instead of "not enough history",
 * and a metric with no day yet says the same instead of "no data". The values themselves stay the real partial sums.
 * While importing, a comparison needs the whole prior window (a gap there is always the old side).
 * No comparison asked for (compare null): values only, no delta and no reason for the missing delta.
 */
export function kpis(s: Summary, opts: { backfilling?: boolean } = {}): Record<KpiId, Kpi> {
  const priorDays = s.compare ? daysIn(s.compare) : 0;
  // importing runs newest-first, so a gap is always in the prior window and would bias the delta up: it must be complete then
  const comparable = s.compare !== null && s.current.days >= Math.ceil(s.period * MIN_COVERAGE) && s.prior.days >= (opts.backfilling ? priorDays : Math.ceil(priorDays * MIN_COVERAGE));
  const short: MissingReason | null = s.compare === null ? null : opts.backfilling ? 'backfilling' : 'not_enough_history';
  const empty: MissingReason = opts.backfilling ? 'backfilling' : 'no_data';
  const fewFollowers: MissingReason = s.current.followers !== null && s.current.followers < 100 ? 'needs_100_followers' : empty;
  const asked = <T>(v: T): T | null => (s.compare ? v : null);
  return {
    followers: kpi(s.current.followers, asked(s.prior.followers), true, empty, short),
    reach: kpi(s.current.reach, s.prior.reach, comparable, empty, short),
    views: kpi(s.current.views, s.prior.views, comparable, empty, short),
    engagementRate: kpi(er(s.current), er(s.prior), comparable, empty, short),
    // media history comes from the post backfill, not from daily snapshots, so post counts always compare
    posts: kpi(s.current.posts, asked(s.prior.posts), true, 'no_data', short),
    netFollows: kpi(s.current.netFollows, s.prior.netFollows, comparable, fewFollowers, short),
  };
}
