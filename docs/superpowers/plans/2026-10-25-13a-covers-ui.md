# Plan 13a: Covers UI — `MediaThumb`, Posts grid, Stories filmstrip, Calendar covers, post detail drawer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the real cover of every post, Reel and Story that Plan 11b stores in the private `covers` bucket: one accessible `MediaThumb` (format-aware aspect, format badge, play glyph, carousel count, "expired" ribbon, skeleton, never a broken image), a **Grid | Table** toggle on the Posts tab (grid by default on phones), a **filmstrip per day** on the Stories tab, covers in the Calendar, and a **post detail drawer** (cover, caption, owner-timezone date/time, format, key numbers, tags, permalink) with an `action` slot that Plan 13b fills with "Open Post Lab".

**Architecture:** No migration, no new route, no new dependency. The three existing owner-session reads (`loadPostRows`, `loadStories`, `loadMonthMedia`) also select `cover_status` and `children_count`; the pure models (`PostView`, `StoryView`, `CalendarItem`) carry them as `cover` and `slides`. `MediaThumb` requests `/api/media/<id>/cover` (Plan 11b's owner-only route, unchanged) only when `cover = 'ok'`, with a plain lazy `<img>` inside a fixed-aspect box. `MediaDrawer` is one `ResponsiveDialog` per item opened by its own trigger (Radix returns focus to it). The Posts grid is a third rendering mode of the shared `DataTable` (same sort, "Show more" and empty state as the table). The Stories filmstrip groups Stories by owner-timezone day with a pure `storyDays()`. Pages stay wiring only.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, next-intl 4, shadcn/Radix (`ResponsiveDialog`, `Button`, `Badge`, `Skeleton`), lucide-react icons (installed), Vitest + Testing Library + jsdom 29. **New dependencies: none.**

**Spec:** `docs/superpowers/specs/2026-10-15-creator-toolkit-design.md` §4 "Phase B — Visual content library" (UI part, approved), §0b (desktop-first, own accounts only), §8 (cross-cutting rules); `docs/SPEC.md` §5 (`media`), §8 (UI). Plan 11b (`docs/superpowers/plans/2026-10-22-11b-capture-extras.md`: bucket, columns, cover route) and Plans 12a/12b (Time Scope, `listRange`) are merged and consumed as they are on `main`. Project rules: `CLAUDE.md` (binding).

**Dry run:** see "Dry-run result" at the end of this file.

## Decisions taken in this plan (owner: please confirm the ones marked ⚠)

- **Plain `<img>`, not `next/image`.** The cover route is private (owner session cookie, `Cache-Control: private, immutable`); Next's image optimizer fetches the source on the server WITHOUT the viewer's cookies (it would get 401) and keeps results in a shared server cache (a privacy leak if it worked). Covers are already small originals (50–150 KB, spec §4). So: `<img loading="lazy" decoding="async">` with the `@next/next/no-img-element` rule disabled on that one line, with the reason (the same pattern as the 2FA QR code).
- **The image is requested only when `cover_status = 'ok'`.** `pending` / `unavailable` / `failed` show a type-icon placeholder without any request; a load error (deleted object, expired session) switches to the same placeholder — never a broken-image icon. Until the image has loaded, a skeleton fills the fixed-aspect box (no layout shift); the image then fades and un-blurs in with `motion-safe:` classes only (light CSS motion, lib/motion.ts's rule; no JS animation).
- **Aspect from the format** (spec §4: 4:5 feed image, 9:16 Reels and Stories, 1:1 carousel), overridable by a class (tailwind-merge resolves `aspect-*` conflicts): the Posts grid uses a uniform 4:5 crop like Instagram's profile grid, the table and the Calendar use small squares, the drawer and the filmstrip show the true aspect.
- **Badges are decorative** (`aria-hidden`): format icon, a play glyph on Reels, the slide count on carousels. The "Expired" ribbon is real text (a state). Alt text = the caption snippet (spec), else the format name; the placeholder is `role="img"` with "<name> (<why there is no cover>)".
- ⚠ **Grid | Table lives in the URL** (`?view=grid|table`; no parameter = automatic: grid below `md`, table from `md`, CSS only — both rendered, like `DataTable` already does for its phone cards). Why the URL and not a per-viewer preference: every other control of the account page is URL state (tab, filters, Time Scope), so Back, sharing and saved links keep it, and the server renders the chosen view with no hydration flash (a localStorage choice can only be applied after hydration; `window.matchMedia` for layout is forbidden). The filter form, its Reset link and the Time Scope bar keep `view`. Switching is a link (server re-render, like a filter); the tab's Suspense key ignores `view`, so the current view stays on screen (top progress bar running) until the other one streams in.
- **The grid is a mode of the shared `DataTable`** (`tile` + `view` props): grid and table share the sort state, the phone sort bar, "Show more" (50 per page) and the empty state — no second implementation. Without `tile`, `DataTable` is unchanged (every existing table).
- **Post detail drawer = one `ResponsiveDialog` per item, opened by `ResponsiveDialogTrigger asChild`**: Radix traps focus, closes on Esc and returns focus to the trigger; the content mounts only while open (50 roots per page cost nothing). It is generic (`title`, `description`, `stats`, `children`, `action`) so posts, Stories and Plan 13b use the same component. Tags are assignable inside the drawer (the existing `TagPicker`), so grid tiles stay light; the table keeps its Tags column.
- ⚠ **The drawer shows the caption snippet already loaded (80 characters)**, not the full caption: the full text would add up to 2,200 characters per post to every Posts page payload; Plan 13b's Post Lab shows the whole caption.
- **Stories: a filmstrip per owner-timezone day** — days newest first, the Stories of a day in posting order (left to right, like Instagram plays them), each day a horizontally scrolling strip; a frame = 9:16 cover (drawer trigger) + time + "Live" badge or "Expired" ribbon + views, reach, replies, exit rate + the snapshot hint + permalink. The views sparkline moves into the Story's drawer (the frame is too narrow). `storyDays()` is pure and tested.
- ⚠ **The 200-Stories cap stays (`STORY_LIMIT`), and the tab keeps saying so.** Lifting it simply is not possible without one of: (a) a new SQL function returning each Story's final snapshot + snapshot count + views series — the Stories tab and the export would then depend on a migration that is not applied anywhere yet (12b's is not either), (b) reading only each Story's latest snapshot — drops the views sparkline and the export's "Snapshots" column, or (c) reusing 12b's `explorer_media` — it does not return replies, exits, taps or the series. 200 newest Stories per account per range is also a sane bound for a cover filmstrip. Upgrade path (ponytail note in `loadStories`): a `story_finals(p_account, p_from, p_to)` `security invoker` function, applied before the code that calls it.
- **Calendar:** covers in the day list always (one day on `md+`; lazy images in the phone agenda), covers inside grid cells only when the grid is a month view (≤ 6 weeks, `COVER_WEEKS`): a 1y/"all" grid (up to 262 weeks) keeps its count chips only, so no extra images or DOM per cell. The Calendar does not open the drawer: it reads no numbers (metadata-only read keeps 1y/"all" fast).
- **Nothing else changes:** the cover route, the sync, the exports and the Explorer are untouched; no Meta calls; no Meta metric names.
- **Skipped (handed over by 12a as optional): the Tags page and audience history following the Time Scope** — not trivial: tag stats are all-time today and need the bar, a ranged read and the nav carrying the scope; audience history needs a history read and chart that do not exist yet.

## Global Constraints

- Ponytail: smallest thing that works; no abstraction with one implementation (`MediaThumb` has 4 callers, `MediaDrawer` 3, `storyDays` 1 pure helper with its test); **no new dependencies**.
- TypeScript strict. No Meta metric names added or changed. **No migration.**
- Reads: OWNER SESSION client only (unchanged readers gain two columns); explicit column lists; fixed error messages. The cover image is only ever requested through `/api/media/<id>/cover` (same origin, owner-only); no signed URLs, no public bucket, nothing for the service worker.
- Every UI string via next-intl; ALL new keys are added by Task 1 in BOTH `messages/en.json` and `messages/zh-CN.json` (real Simplified Chinese, full-width punctuation); later tasks only read them. `tests/messages.test.ts` enforces parity + placeholders.
- Theming: semantic tokens only (`bg-muted`, `bg-background/80`, `text-muted-foreground`, `ring-ring`); no raw colours — overlays on photos use `bg-background/80 text-foreground`, readable in light and dark.
- Responsive 360 / 768 / 1280; CSS breakpoints only (no `matchMedia`/`useMediaQuery` for layout); `min-w-0` + `truncate` on user text; no fixed pixel widths on layout containers (frames and thumbs use rem sizes inside scrollers/cells).
- Motion: only CSS `motion-safe:` transitions/pulse; nothing heavy, so no `useHeavyMotion` gate is needed.
- UI kit: build from `components/ui/` + `components/shared/`; dialogs use `ResponsiveDialog*`; density is un-layered (`h-*`/`p-*` on shadcn `Button`/`Input`/`Card`/table cells are ignored — none are relied on here). No `npx shadcn` call is needed in this plan.
- Dates, times and numbers only via `lib/format.ts` (`formatDateTime`, `formatTime`, `formatDay`, `formatCompact`, `formatNumber`, `formatPercent`).
- Every link keeps the Time Scope (`scope` params) and the page's own parameters.
- Tests: Vitest timeout 20 s; `tests/posts-tab.test.tsx` "500 posts" is known slow (≈ 9 s alone): rerun once on a timeout / "worker start timeout" before concluding; never chain a commit after a piped command.
- `npm run check` passes after every task. Commits: conventional, `git add` specific paths, `git commit -m "<msg>" -m "Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>"`. Don't push.

## Review Focus

2. **Never a broken image; no layout shift:** fixed-aspect box + skeleton + placeholder on error, also when the image finished before hydration → Task 3 tests.
3. **Keyboard and focus:** the drawer opens from a real button, closes on Esc, returns focus to its trigger; the "Open Post Lab" slot renders inside the dialog → Task 4 tests.
4. **Behaviour kept:** every existing Posts/Stories/Calendar test passes unchanged except the two readers' shape assertions (Task 2); the filter form, Reset, Time Scope and Explorer links keep their parameters (+ `view`) → Task 6 tests.
5. **1y Calendar performance:** grid cells get covers only for ≤ 6 weeks → Task 8 "a year grid has no cell covers".
