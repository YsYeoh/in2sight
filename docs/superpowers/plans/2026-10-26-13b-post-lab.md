# Plan 13b: Post Lab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One page per post, Reel, carousel and Story — `/accounts/[id]/media/[mediaId]` — that answers "how did this one do, compared with my own normal, and why": a header with the cover, caption, time, format, editable tags and the gone/expired state; a scorecard where every number has its percentile and difference vs the median of the account's last 30 or 90 posts of the same format and a verdict chip (Breakout / Above typical / Typical / Below typical / Too early) behind a sample-size guard; a velocity curve (cumulative reach/views at 1 h, 6 h, 24 h, 48 h, 7 d against the median curve of the same posts); a watch-time panel for Reels; a navigation funnel and a sequence view of the day's Stories; a caption lab; and a strip of similar posts. Every surface that lists posts (Posts table/grid, the post drawer, the Calendar day list, the Explorer item panel) links into it.

**Architecture:** One additive migration adds two small `security invoker` SQL functions (RLS still applies, execute for `authenticated` only): `post_lab_latest(ids)` returns the latest known value of every metric column per media (a snapshot taken on a busy tick can lack its extras; the previous one has them) and `post_lab_points(ids, marks, tols)` returns, per media and checkpoint, the snapshot nearest to "posted + mark" inside a tolerance window — one `DISTINCT ON` instead of shipping ~7,000 snapshot rows through PostgREST's 1,000-row pages. The checkpoint table (marks and tolerances) lives once, in TypeScript, and is passed in. Everything else is plain owner-session selects (the media row, its same-format predecessors, the day's Stories, the posting-day follower counts). The reader turns rows into null-safe `LabItem`s (Meta names such as the `BIO_LINK_CLICKED` action type stay in `lib/instagram/metrics.ts`); pure functions in `lib/analysis/post-lab.ts` (scorecard, percentiles, verdict, velocity, Story funnel and sequence, similar posts) and `lib/analysis/caption.ts` (caption features and the with/without split) build the page model. The page is wiring only; the view is split by section into small client components.

**Tech Stack:** Next.js 16.4 App Router, TypeScript strict, Supabase Postgres (SQL functions, RLS), `@supabase/supabase-js` owner-session client, next-intl 4, Recharts 3 (installed), Vitest 5 + Testing Library + jsdom 29. **New dependencies: none.**

**Spec:** `docs/superpowers/specs/2026-10-15-creator-toolkit-design.md` §5 "Phase C — Post Lab" (approved design), §0b (engagement rate both ways, desktop-first, own accounts only), §8 (cross-cutting rules); `docs/SPEC.md` §5, §7; Plan 13a `docs/superpowers/plans/2026-10-25-13a-covers-ui.md` (consumed: `MediaThumb` and the post drawer, see "Assumptions about 13a"). Project rules: `CLAUDE.md` (binding).

**Dry run:** see "Dry-run result" at the end of this file.

## Decisions taken in this plan (owner: please confirm the ones marked ⚠)

- **Two small SQL functions, everything else plain selects.** A post with its 90 peers has ~7,000 snapshots (hourly for 48 h, daily to day 30, the day-7 checkpoint); picking "the snapshot nearest to posted + 6 h" per media is one `DISTINCT ON` in SQL but 7+ pages of 1,000 rows through PostgREST. `security invoker` keeps RLS in charge. The media row, the peers, the day's Stories and the follower counts are ordinary owner-session selects (one page each).
- **Peers = the same account's posts of the same format published BEFORE this one, newest first: 30 by default, 90 with the toggle** (`?peers=90`). The post itself is never a peer. Reason: a fixed reference that does not drift when newer posts arrive, and the same "previous posts" idea as the "taking off" flag (`lib/analysis/flags.ts`). The reader always reads 90; the scorecard and the velocity medians use the first 30 or 90; the caption lab and the similar strip use all that were read.
- **Sample guard = `MIN_PRIOR_POSTS` (5), Breakout = `TAKING_OFF_RATIO` (2× median), both imported from `lib/analysis/flags.ts`,** so the verdict and the "taking off" alert can never disagree. A comparison (median, percentile, difference) needs ≥ 5 peers that HAVE that number; below that the row says "Needs 5+ measured posts to compare" (the existing `analysis.reasons.few_posts` text).
- **Percentile = mid-rank:** (peers below + ½ × peers equal) ÷ peers × 100, rounded. Difference vs median: relative for counts (`+23%`), percentage points for rates (`+1.2 pp`).
- **Verdict uses reach** (as the flag and the best-time analysis do): Breakout ≥ 2× median; Above typical ≥ 75th percentile; Below typical < 25th; else Typical. **"Too early" rule:** a feed post / Reel younger than 24 h (`MIN_AGE_HOURS`) is always Too early; between 24 h and 7 days (`CHECKPOINT_DAYS`) only Breakout and Above typical are given (reach only grows, so a lead is real), otherwise Too early; from day 7 the full scale. A Story gets Breakout/Above while live and the full scale once expired (its final numbers). No verdict at all (a reason instead) without reach, under the sample guard, or for a Story Instagram never measured (under 5 viewers, error 10).
- **Velocity checkpoints (one table in `lib/analysis/post-lab.ts`, passed to SQL):** 1 h ± 30 min, 6 h ± 60 min, 24 h ± 2 h, 48 h ± 3 h, 7 d ± 12 h; Stories use 1 h, 6 h, 24 h. A checkpoint is the snapshot NEAREST to posted + mark inside its window. **Never invented:** no window hit → no point (the line breaks, `connectNulls={false}`); a peer without that point simply does not count for that point's median, and a median point needs ≥ 5 peers. The sentence "At 24 h this post had 2.3× the median reach of 12 earlier Reels" uses the latest checkpoint where both exist.
- **Latest numbers = the latest KNOWN value of each column** (`post_lab_latest`): the extras of a snapshot can be missing on a busy tick (20 extra calls per account run) while the snapshot before has them. Story numbers are their final numbers (Stories are only measured while live).
- **Scorecard rows per format.** Feed/carousel: reach, views, interactions, engagement rate, save rate, share rate, follows per 1,000 reach, profile visits, link taps. Reels: the same, follows and profile visits marked "Instagram doesn't report this for Reels" (verified, `docs/META_PROBE_RESULTS.md`), plus the watch-time panel (avg watch, total watch, skip rate vs your median; lower skip rate is better). Stories: reach, views, interactions (Instagram's total), replies, share rate, follows per 1,000 reach, profile visits, link taps, plus the funnel and the sequence; no engagement/save rate (Stories have no likes/saves; every existing analysis leaves them out). A missing number always carries a reason (unsupported / not captured / not measured / under 5 viewers / no follower count), never 0.
- **Engagement rate both ways (§0b):** per reach (default, = SPEC §7) or per followers (`?er=followers`): interactions ÷ the account's follower count on the posting day (`account_daily.followers`; each peer uses its own day). Days without a follower count give a reason, not a number.
- **Link taps** = `profile_activity`'s `BIO_LINK_CLICKED` action (Meta's `action_type` value; the name goes into `lib/instagram/metrics.ts`, read case-insensitively).
- **Post Lab metrics are a small table in `lib/analysis/post-lab.ts`, not entries in the Explorer registry `lib/metrics.ts`.** They are per-item snapshot values; the registry computes Explorer rollups from SQL parts, and save/share/follow rates or watch time would need new SQL parts there. A new Post Lab number is still one entry (+ one label).
- **Story sequence:** the account's Stories of the same owner-timezone day, oldest first, with reach, "% of the first Story's reach" and exit rate (exits ÷ views, as the Stories tab); best/worst frame = lowest/highest exit rate among ≥ 2 measured frames. Story funnel: forward taps, back taps, exits, swipes forward, each as a count and a share of views, plus replies.
- **Caption lab:** length (characters), hashtags (count + list), mentions (count), emoji (count), question (`?`/`？`), call-to-action words (a short en + zh list in `lib/analysis/caption.ts`). The with/without comparison runs over the peers that were read (same format, ≤ 90) and only from **20 measured posts** (spec), each side needing ≥ 5 posts; it compares median reach ("Posts with a question: 1.2K median reach (n = 14) vs 900 (n = 31)") and says plainly that this is a pattern in your own posts, not a cause. No caption lab for Stories (no captions).
- **Similar posts:** up to 6 peers, those sharing a tag first, then the newest; each links to its own Post Lab.
- **Back link and links in keep the Time Scope:** the Post Lab has no scope of its own, but it carries the canonical scope parameters (`scopeQuery(parseTimeScope(sp))`, never echoed raw) and puts them on its back link (the account's Posts or Stories tab) and on every link it renders; every link into it carries the referring page's scope. Browser Back covers "where did I come from" (Calendar, Explorer).
- **Route group move:** `app/(app)/accounts/[id]/page.tsx` + `loading.tsx` move into `app/(app)/accounts/[id]/(tabs)/` (same URL) — at `[id]/` the account skeleton would also wrap the Post Lab (`tests/route-loading.test.tsx` forbids that; same pattern as `accounts/(list)/`).
- **Missing migration = a clear page, not a crash:** if PostgREST answers "function not found" (`PGRST202`) the Post Lab shows "The Post Lab needs a database update" with the runbook pointer; no other page calls the new functions (the links into the Post Lab are plain links), so nothing else depends on the migration.
- **Another account's media id gets nothing:** the media row is read with `account_id = <the URL's account>` under RLS; no row → 404.
- **No new dependencies; no Meta calls; no capture changes; no new Meta metrics** (one constant name for an action type that is already captured).

## Open questions for the owner (the plan implements the default shown)

1. Peers = the 30 (toggle: 90) same-format posts published before this one? **Default: yes.** Alternative: the newest 30 of the account whatever the post's age.
2. Sample guard 5 measured peers (same as the "taking off" flag)? **Default: yes** (5 is coarse for percentiles; 10 would hide comparisons on small accounts for months).
3. Verdict on reach for every format (Reels too)? **Default: yes** (views is Instagram's headline for Reels; switch is one line).
4. "Too early" before day 7 unless the post already leads (Breakout/Above)? **Default: yes.**
5. Caption lab compares the same format only? **Default: yes** (mixing Reels and images would compare formats, not captions).
