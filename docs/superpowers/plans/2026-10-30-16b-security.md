# Plan 16b: Security (change password, forgot / reset password, sign out other devices) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Parallel worktree agents: read `docs/superpowers/implementer-rules.md` first.

**Goal:** The owner can (1) **change the password** in Settings → Security (current + new + confirm, strength meter, show/hide toggle), after which every OTHER device is signed out; (2) **sign out every other device** with one button (Supabase Auth cannot list the current user's sessions, so there is no session list: see Decisions); (3) **reset a forgotten password**: "Forgot password?" on the login page → `/login/forgot` (email, always the same generic answer) → Supabase recovery email → `/auth/confirm` (a "Continue" button, so mail scanners cannot burn the link) → recovery session (aal1) → the EXISTING 2FA step `/login/verify` → `/login/reset` (new password + meter) → every session signed out → `/login` with "Password changed, sign in again". A recovery session at aal1 reaches no owner page and no owner data (the proxy, `requireOwner()` and `is_owner()` already guarantee it; this plan adds tests that prove it for the new routes).

**Architecture:** Pure rules in `lib/auth/password-rules.ts` (`passwordStrength`, the form state types) and `lib/auth/attempts.ts` (a cookie attempt counter: friction, not a security boundary). Supabase calls in two small modules taking a client: `lib/auth/recovery.ts` (`isValidEmail`, `isTokenHash`, `requestPasswordReset` with a fixed minimum duration, `confirmRecovery` via `verifyOtp({ type: 'recovery', token_hash })`, `hasRecentEmailProof` on the verified JWT `amr` claim, `hasRecoveryProof`) and `lib/auth/password.ts` (`changePassword`: re-authenticates the CURRENT password with a separate, non-persisting client, revokes that check session at once, then `updateUser` on the owner session, then `signOut({ scope: 'others' })`; `setNewPassword` for the recovery flow, then `signOut({ scope: 'global' })`). Server actions (`requireOwner()` first wherever a session is required): `app/(app)/settings/security-actions.ts`, `app/login/forgot/actions.ts`, `app/auth/confirm/actions.ts`, `app/login/reset/actions.ts`; `app/login/verify/actions.ts` sends a fresh recovery session to `/login/reset` instead of `/overview`. Route policy: exactly two new signed-out paths (`/login/forgot`, `/auth/confirm`), `/auth/confirm` reachable in every signed-in state like `/auth/signout`, `/login/forgot` joins the entry pages; `/login/reset` gets NO exemption (signed-out → `/login`, aal1 with 2FA → `/login/verify`). UI: `PasswordInput` (show/hide), `PasswordForm` (meter; used by both Settings and the reset page), `SignOutOthersButton`, `ForgotForm`, `RecoveryConfirmForm`, and the Security section content (`components/settings/sections/SecuritySection.tsx`, Plan 16a's placeholder). **No migration, no new dependency, no sessions table.**

**Tech Stack:** Next.js 16.4 App Router (server actions, `cookies()`), React 19.3, TypeScript strict, `@supabase/ssr` 0.12.7 + `@supabase/supabase-js` / `auth-js` 2.117.3 (already installed), next-intl 4, shadcn via the shared pieces (`Card`, `Input`, `Button`, `FormField`, `LoadingButton`), Vitest + Testing Library + jsdom. **New dependencies: none.**

**Spec:** `docs/superpowers/specs/2026-10-15-creator-toolkit-design.md` §0b ("change password (Settings → Security) and forgot/reset password via Supabase recovery email (needs custom SMTP + Site URL)"; round 4 had "Forgot-password email: skip for now", the owner has since asked for it: this plan supersedes that line), §7 ("Security (2FA, active session/sign out, password)"), `docs/TODO.md` §6b (both bullets). Project rules: `CLAUDE.md` (binding; Security rules). Built **after Plan 16a** (Settings shell and sections, planned in parallel): see "Contract with Plan 16a".

**Scratch run:** see "Scratch-run result" at the end (filled in after the dry run).

## Decisions taken in this plan (owner: please confirm the ones marked ⚠)

- **Active sessions = "Sign out other devices", no list.** auth-js has no call that lists the current user's sessions (only the Admin API and SQL on `auth.sessions`, both service-role, and this plan keeps the service role out of auth flows). So Settings → Security shows a short explanation and ONE button, `signOut({ scope: 'others' })`. The existing "Sign out" (`signOutAction` → `signOut()` = default scope **global**) already signs out every device including this one; this plan does not change it and the runbook says so. ⚠ Open question 6 (a list would need a service-role read of `auth.sessions`: not built, no sessions table invented).
- **Sign-out is not instant on other devices:** Supabase revokes refresh tokens; an access JWT already issued stays valid until it expires (Supabase docs, quoted above; `getClaims()` verifies the JWT locally and RLS checks only the JWT). With the default JWT expiry (3,600 s) another open device keeps working for up to 1 hour. The UI says so ("up to 1 hour"); the owner may lower the JWT expiry (⚠ Open question 7). The same ceiling applies after a password change or reset.
- **Change password = re-authenticate first, through a SEPARATE client.** `changePassword` signs in with the owner's email (from the verified session, never from the form) and the typed current password on a fresh `createClient(url, publishableKey, { auth: { persistSession: false, autoRefreshToken: false, detectSessionInUrl: false } })` (memory only, no cookies, nothing written to the browser), checks that the returned user id is the owner's, and immediately calls `signOut({ scope: 'local' })` on that client so the check session does not linger (`scope: 'others'` afterwards revokes it anyway). Only then `updateUser({ password })` on the OWNER's cookie session (aal2: `requireOwner()` already redirects an aal1 session with 2FA to `/login/verify`), then `signOut({ scope: 'others' })` on the owner session. Failure of the check → `wrong_password` (one message for every sign-in failure except a rate limit) and no update. The check session is aal1 and never reaches owner data (`is_owner()` needs aal2 once a factor exists). ⚠ Open question 1.
- **Password rules (`passwordStrength`, pure, no dependency):** at least `PASSWORD_MIN = 12` characters (NIST SP 800-63B favours length over composition; 12 is a common minimum for a single high-value account), at most `PASSWORD_MAX_BYTES = 72` UTF-8 bytes (bcrypt, which Supabase Auth uses, ignores bytes after 72: a longer password would be silently truncated), at least `PASSWORD_MIN_DISTINCT = 5` different characters (`aaaaaaaaaaaa`, `abcabcabcabc` refused), and not containing the email's local part (3+ characters, case-insensitive). Meter: 12–15 characters = 1, 16–19 = 2, 20+ = 3, +1 when 3 or more of {lowercase, uppercase, digit, other} are present, capped at 4; any broken rule = 0. Labels: Too weak / Fair / Good / Strong / Very strong. The same function runs in the browser (meter) and on the server (the decision). The owner sets Supabase's own minimum length to 12 too (prerequisite). ⚠ Open question 5 (breached-password check: not built).
- **Rate limiting without new infrastructure** (`lib/auth/attempts.ts`): an HttpOnly cookie counter `count.firstAtMs`, `SameSite=Lax`, `Secure` in production, path `/`. Change password: `PASSWORD_LIMIT = { max: 5, windowMs: 900_000 }` wrong current passwords → `rate_limited` without calling Supabase. Forgot: `FORGOT_LIMIT = { max: 1, windowMs: 60_000 }` (matches Supabase's one request per user per 60 s on `/recover`) → `cooldown`. **What it does NOT protect:** anyone can drop the cookie (curl, a private window). It only stops the honest browser from hammering; the real limits are Supabase's: `/token` 150 per 5 min per IP, `/recover` one per user per 60 s, and the project-wide email cap (custom SMTP: the owner sets e.g. 10 per hour). All our Auth calls come from Vercel's server IPs, so the per-IP limits are shared by every visitor of this app. A durable per-account lockout would need a table (migration) or a KV store: not built (`ponytail:` comment in `attempts.ts`). ⚠ Open question 3.
- **Forgot password never reveals anything about the account:** the answer is `{ status: 'sent' }` for every syntactically valid email, whether the account exists, whether Supabase rate-limited it, refused it or threw. Supabase's `/recover` answers the same for unknown emails (docs). Timing: `requestPasswordReset` always takes at least `RESET_MIN_MS = 2000` ms (the call runs, then the remainder is awaited), so a fast "no such user" path is not visible; if the real SMTP send ever takes longer than 2 s the difference shows: the runbook times both cases. Only a malformed email gets its own message (`invalid_email`, decided by the format alone, before any call). The `cooldown` answer depends only on the visitor's own cookie, never on the account.
- **Only the owner can ever reset:** sign-ups are disabled (`docs/RUNBOOK_AUTH.md` "Before the first login"; the runbook re-checks the switch), so the owner is the only user. Even if another user existed, a reset session is still gated by `is_owner()` / `requireOwner()` (not the owner → `/auth/signout`). The app never calls the Admin API here and never looks the email up itself (that lookup would be an enumeration oracle).
- **Email bombing:** our cookie (one per minute per browser) + Supabase's one per user per 60 s + the project-wide email cap. Worst case without cookies: about one email a minute to the owner's inbox, capped by the hourly limit the owner sets. A CAPTCHA (Supabase supports hCaptcha / Turnstile) is NOT built. ⚠ Open question 3.
- **Recovery link = token hash on our own page, POST to use it.** The email template (owner prerequisite) links to `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`, the pattern the Supabase SSR docs give for password reset. `/auth/confirm` is a PAGE: a GET only renders "Continue" (mail scanners that pre-open links therefore cannot consume the one-time token); the button posts a server action (`confirmRecoveryAction`; Next.js rejects server-action POSTs whose Origin does not match the host, which is the CSRF guard) that calls `verifyOtp({ type: 'recovery', token_hash })` on the cookie client. **There is no `next` / `redirectTo` parameter anywhere:** success always goes to the fixed path `/login/reset`, failure stays on the page with `link_invalid`; a `next` in the email link is ignored. The default Supabase template (`{{ .ConfirmationURL }}`) would land on `/?code=…`, which the proxy sends to `/login` and nothing exchanges: harmless, and the runbook catches a missing template change. The page sets `referrer: 'no-referrer'` and `robots: { index: false }`. The token hash appears in Vercel's request log for that one GET (single use, expires after 1 hour, worthless once used): stated in the runbook.
- **A recovery session must still pass 2FA, then has 15 minutes to set the password.** `verifyOtp` gives an aal1 session. The proxy already sends every path except `/login/verify`, `/auth/signout` and (new) `/auth/confirm` to `/login/verify` while 2FA is owed; `is_owner()` returns false at aal1 while a verified factor exists. After the code, `verifyMfaAction` redirects to `/login/reset` (instead of `/overview`) when `hasRecoveryProof` is true. `/login/reset` (page AND action) requires `requireOwner()` (aal2 + owner) AND `hasRecentEmailProof(claims)`: an `amr` entry with method `recovery`, `otp` or `magiclink` (each means "proved access to the owner's inbox"; the app offers no magic-link login, and an attacker cannot receive the owner's mail) whose `timestamp` is at most `RECOVERY_WINDOW_SEC = 900` s old. A stolen aal2 session WITHOUT that claim cannot set a password without the current one (the JWT is signed by Supabase; the claim cannot be forged). The string-only `amr` format (no timestamps) fails closed. ⚠ Open question 2.
- **After a reset: sign out EVERYWHERE and sign in again.** `setNewPassword` calls `updateUser({ password })` then `signOut({ scope: 'global' })` (revokes the recovery session too); the action redirects to `/login?reset=done` ("Password changed. Sign in with your new password."). One extra 2FA code for the owner; in exchange the recovery-derived session ends at once and the new password is proven immediately. If the global sign-out fails, the password is still changed and the owner may be bounced to `/overview` by the proxy (session survived): no error is shown (rare; the runbook checks the normal path).
- **After a change in Settings:** this device stays signed in, the others are signed out (`scope: 'others'`). If that sign-out fails the action still reports success with `othersSignedOut: false` and the UI says "use Sign out other devices below".
- **Errors are keys** (`PasswordError`): `missing_fields | mismatch | weak | wrong_password | same_password | rate_limited | link_expired | unexpected`; forgot: error `invalid_email`, status `sent | cooldown`; confirm: `link_invalid`. Supabase `same_password` → `same_password`, `weak_password` → `weak`, HTTP 429 or a code containing `rate_limit` → `rate_limited`, everything else (including `reauthentication_needed`) → `unexpected`. No Supabase message text ever reaches the UI or a log.
- **No logging at all** in the new auth files (no `console.*`): a guard test enforces it. Passwords travel only in POST bodies of server actions (never in a URL, never in a return value, never in an error).
- **Routes** (exact paths; `/auth/*` and `/login/*` are not tab paths, so `FrameBreakout` already takes them out of a tab frame: tests added): `/login/forgot` (signed out: shown; signed in at aal2 or without 2FA: entry page → `/overview`; 2FA owed → `/login/verify`), `/auth/confirm` (every state, like `/auth/signout`), `/login/reset` (NO exemption: signed out → `/login`; 2FA owed → `/login/verify`; otherwise the page, which checks owner + claim).
- **The login page** gets a "Forgot password?" link under the form and a `role="status"` notice for `?reset=done` (the only accepted value; anything else shows nothing).
- **Settings → Security content:** the existing `TwoFactorCard` unchanged (2FA status + today's enrol / disable flows, not rebuilt), a "Password" card (`PasswordForm` with the current-password field and a hidden `username` field for password managers), a "Signed-in devices" card (explanation + `SignOutOthersButton`). The owner's email stays where Plan 16a puts it.

## Open questions for the owner (the plan implements the default shown; L = needs a LIVE check in `docs/RUNBOOK_SECURITY.md` before relying on it)

1. **L1 — the current-password check.** A `signInWithPassword` on a separate memory-only client creates a real (aal1) session in `auth.sessions`; we revoke it with `signOut({ scope: 'local' })` at once and `scope: 'others'` revokes it again. Unverified: that the local sign-out revokes exactly that session and not the owner's cookie session; that the extra sign-in does not trigger anything else (Supabase sends no "new sign-in" email by default; if the owner enabled a security-notification email, one arrives per check). **Default: as built; RUNBOOK §3 checks the owner stays signed in and other devices are signed out.** Alternative if it misbehaves: `updateUser({ password, current_password })` with Supabase's "require current password" setting (OQ 4).
2. **L2 — the `amr` claim of a recovery session.** auth-js lists `AMRMethods` without `recovery` (`password, otp, oauth, totp, mfa/totp, …, magiclink`); GoTrue may label a recovery login `recovery` or `otp`. **Default: accept `recovery`, `otp` and `magiclink`, each with a timestamp ≤ 900 s old, object format only.** Also unverified: that the entry survives the TOTP step (the session is upgraded in place). **Safe failure:** if the claim is missing, `/login/reset` shows "This reset has expired" and nothing changes; the owner falls back to today's way (assistant + Auth admin API). RUNBOOK §2 step 6.
3. **Rate limiting and CAPTCHA.** Cookie friction + Supabase's limits only; no durable lockout, no CAPTCHA. **Default: enough for a single-owner app with a 12+ character password and TOTP.** Upgrade paths: a small `auth_attempts` table (migration) or Supabase CAPTCHA (dashboard switch + a widget = a new script origin in the CSP).
4. **L4 — Supabase "Secure password change" / "require current password" switches.** If "Secure password change" is ON, `updateUser({ password })` on a session older than 24 h answers `reauthentication_needed` (→ `unexpected`). **Default: the owner keeps both OFF (this app checks the current password itself); RUNBOOK §0 records their state.** Unknown: whether the hosted dashboard exposes "require current password" at all, and what it does to the recovery flow.
5. **Breached-password check** (Supabase "leaked password protection" needs a paid plan; a word list would be a dependency). **Default: not built;** the 12-character minimum + 5 distinct + no email name + TOTP.
6. **A real session list** (device, last seen) needs a service-role read of `auth.sessions`. **Default: not built;** "Sign out other devices" + the existing "Sign out" (global) cover the need.
7. **JWT expiry** (how long another device keeps working after "Sign out other devices", a password change or a reset). **Default: Supabase's 3,600 s, UI says "up to 1 hour".** Lowering it (e.g. 900 s) means more token refreshes; if the owner changes it, the UI string `auth.security.sessionsNote` must change too.
8. **L8 — recovery link expiry and reuse.** Supabase's email OTP expiry defaults to 3,600 s; a token hash is single-use. **Default: the UI says "works once and expires after 1 hour"; RUNBOOK §2 opens a used link (→ "expired or already used") and an old one.**
9. **L9 — PKCE and token hash.** The cookie client (`@supabase/ssr`, PKCE flow) calls `resetPasswordForEmail`, which also stores a code-verifier cookie in the requesting browser; `verifyOtp({ token_hash })` does not need it (the Supabase SSR docs use exactly this pair), so the link also works on another device. **Default: as documented; RUNBOOK §2 opens the link on a different device than the one that asked.**
10. **Template language.** Supabase has ONE recovery template per project (no per-language templates). **Default: one bilingual email (English first, then Simplified Chinese), text in the runbook.**

## Global Constraints

- Ponytail: smallest thing that works. ## Review Focus (safety-critical: authentication)

1. **aal1 → aal2 bypass:** a recovery session (aal1, factor enrolled) reaches only `/login/verify`, `/auth/signout`, `/auth/confirm` → Task 5 "a recovery session at aal1 reaches no owner page" (every page and API path in the test list, including `/login/reset`, `/settings/security`, `/api/export/xlsx`); `resetPasswordAction` / `changePasswordAction` / `signOutOthersAction` call nothing when `requireOwner()` throws → Tasks 9; `is_owner()` (SQL, unchanged) is the third gate for data.
2. **Recovery replay / stale recovery:** single-use token (Supabase, L8), POST-only confirm (scanner-safe), `/login/reset` needs a fresh (≤ 900 s) email-proof `amr` entry checked on BOTH the page and the action → Task 4 `hasRecentEmailProof` table (old, future, string format, wrong method, missing), Task 6 `setNewPassword` "link_expired without a fresh proof, no update".
3. **Session fixation / login CSRF:** the session comes only from `verifyOtp` with a token hash the owner received by email; sign-ups are off so no attacker account exists to fix; after a reset every session (including the recovery one) is revoked (`global`) → Task 6 "signs out globally after the update".
4. **Stolen aal2 session:** cannot change the password without the current one (check client), cannot use `/login/reset` without a fresh email proof, is cut off by "Sign out other devices" within the JWT expiry (documented ceiling) → Task 6, Task 9.
5. **Enumeration:** forgot answers `sent` for every valid email and every Supabase outcome (error, throw, rate limit), with a 2 s floor → Task 4 "same result and at least RESET_MIN_MS for error / throw / success"; `wrong_password` for every check failure; no Admin lookup.
6. **Email bombing:** cookie cooldown + Supabase per-user and project limits (documented ceiling) → Task 7 "cooldown without calling Supabase".
7. **CSRF on the actions:** all state changes are server actions (POST, Origin-checked by Next.js); the only GETs (`/auth/confirm`, `/login/reset`, `/login/forgot`) change nothing → Task 7 "the confirm page GET does not call verifyOtp".
8. **Open redirect:** no `next`, `redirectTo` or `returnTo` is read anywhere; every redirect target is a literal → Task 7 test "a `next` param is ignored", Task 11 guard (grep for `searchParams.get('next')` / `'next'` in the new files).
9. **Passwords in logs / URLs / errors:** no `console.*` (guard), POST bodies only, results carry keys only, the check client is memory-only → Task 11 guard, Task 6 "never returns or forwards Supabase messages".
10. **Timing:** forgot floor (above); change password is owner-only, behind aal2, so its timing reveals nothing new.
11. **Lingering sessions:** the check session is revoked locally at once and by `others` → Task 6 order test `['check.signIn', 'check.signOut:local', 'updateUser', 'signOut:others']`.

```ts
// Password rules for the change and reset forms (Plan 16b). Pure: the browser uses it for the meter, the server for the decision.
// Length over composition (NIST SP 800-63B). bcrypt (Supabase Auth) ignores bytes after 72, so longer is refused, not truncated.
export const PASSWORD_MIN = 12;
export const PASSWORD_MAX_BYTES = 72;
export const PASSWORD_MIN_DISTINCT = 5;

export type PasswordIssue = 'too_short' | 'too_long' | 'too_simple' | 'has_email';
export type StrengthScore = 0 | 1 | 2 | 3 | 4;
export interface Strength {
  score: StrengthScore;
  issue: PasswordIssue | null;
}

export type PasswordFormState = { ok?: boolean; othersSignedOut?: boolean; error?: PasswordError };

const CLASSES = [/[a-z]/, /[A-Z]/, /[0-9]/, /[^A-Za-z0-9]/];

export function passwordStrength(password: string, email?: string | null): Strength {
  const chars = [...password];
  if (chars.length < PASSWORD_MIN) return { score: 0, issue: 'too_short' };
  if (new TextEncoder().encode(password).length > PASSWORD_MAX_BYTES) return { score: 0, issue: 'too_long' };
  if (new Set(chars).size < PASSWORD_MIN_DISTINCT) return { score: 0, issue: 'too_simple' };
  const local = (email ?? '').split('@')[0].trim().toLowerCase();
  if (local.length >= 3 && password.toLowerCase().includes(local)) return { score: 0, issue: 'has_email' };
  const base = chars.length >= 20 ? 3 : chars.length >= 16 ? 2 : 1;
  const bonus = CLASSES.filter((re) => re.test(password)).length >= 3 ? 1 : 0;
  return { score: Math.min(4, base + bonus) as StrengthScore, issue: null };
}
```

```ts
// A cookie attempt counter (Plan 16b): friction for an honest browser, NOT a security boundary (anyone can drop the cookie).
// The real limits are Supabase's (/token per IP, /recover once per user per 60 s, the project email cap).
// ponytail: cookie only; a durable per-account lockout needs a table or a KV store, add one if the runbook ever sees abuse.
export interface Limit {
  max: number;
  windowMs: number;
}
export interface Attempts {
  count: number;
  since: number;
}

export const PASSWORD_LIMIT: Limit = { max: 5, windowMs: 15 * 60_000 };
export const FORGOT_LIMIT: Limit = { max: 1, windowMs: 60_000 };
export const PASSWORD_COOKIE = 'in2s_pw_attempts';
export const FORGOT_COOKIE = 'in2s_forgot_attempts';

/** `count.firstAtMs`; anything malformed, from the future or older than the window counts as a fresh start. */
export function readAttempts(raw: string | undefined, now: number, limit: Limit): Attempts {
  const m = /^(\d{1,3})\.(\d{1,15})$/.exec(raw ?? '');
  if (!m) return { count: 0, since: now };
  const count = Number(m[1]);
  const since = Number(m[2]);
  if (since > now || now - since >= limit.windowMs) return { count: 0, since: now };
  return { count, since };
}

export const isLimited = (a: Attempts, limit: Limit): boolean => a.count >= limit.max;

export const bumpAttempts = (a: Attempts): string => `${a.count + 1}.${a.since}`;

export function attemptCookieOptions(limit: Limit) {
  return {
    httpOnly: true,
    sameSite: 'lax' as const,
    secure: process.env.NODE_ENV === 'production',
    path: '/',
    maxAge: Math.ceil(limit.windowMs / 1000),
  };
}
```

```ts
import type { SupabaseClient } from '@supabase/supabase-js';

// Forgot / reset password (Plan 16b). Nothing here ever tells the caller whether an account exists.
export const RESET_MIN_MS = 2000; // every reset request takes at least this long (no timing oracle)
export const RECOVERY_WINDOW_SEC = 900; // how long after opening the link the new password may be set
const EMAIL_PROOF = new Set(['recovery', 'otp', 'magiclink']); // amr methods that mean "proved access to the inbox"

export type ForgotState = { status?: 'sent' | 'cooldown'; error?: 'invalid_email' };
export type ConfirmState = { error?: 'link_invalid' };

export function isValidEmail(raw: string): boolean {
  const email = raw.trim();
  return email.length >= 3 && email.length <= 254 && /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
}

export const isTokenHash = (raw: string): boolean => /^[A-Za-z0-9_-]{16,256}$/.test(raw);

const sleep = (ms: number) => new Promise<void>((resolve) => setTimeout(resolve, ms));

/** Always resolves, never reveals the outcome, never takes less than RESET_MIN_MS. */
export async function requestPasswordReset(supabase: SupabaseClient, email: string, wait: (ms: number) => Promise<void> = sleep, now: () => number = Date.now): Promise<void> {
  const started = now();
  try {
    // no redirect option: the email template builds the link from the Site URL (docs/RUNBOOK_SECURITY.md §0)
    await supabase.auth.resetPasswordForEmail(email.trim());
  } catch {
    // swallowed on purpose: the answer must not depend on the outcome
  }
  const left = RESET_MIN_MS - (now() - started);
  if (left > 0) await wait(left);
}

/** Exchanges the emailed token hash for a (aal1) recovery session in the cookies. */
export async function confirmRecovery(supabase: SupabaseClient, tokenHash: string): Promise<boolean> {
  try {
    const { data, error } = await supabase.auth.verifyOtp({ type: 'recovery', token_hash: tokenHash });
    return !error && !!data?.session;
  } catch {
    return false;
  }
}

/** True when the verified JWT says this session proved access to the owner's inbox in the last RECOVERY_WINDOW_SEC. */
export function hasRecentEmailProof(claims: unknown, nowSec: number): boolean {
  const amr = (claims as { amr?: unknown } | null | undefined)?.amr;
  if (!Array.isArray(amr)) return false;
  return amr.some((entry) => {
    const e = entry as { method?: unknown; timestamp?: unknown } | null;
    if (!e || typeof e !== 'object' || typeof e.method !== 'string' || typeof e.timestamp !== 'number') return false;
    const age = nowSec - e.timestamp;
    return EMAIL_PROOF.has(e.method) && age >= -60 && age <= RECOVERY_WINDOW_SEC; // 60 s of clock skew allowed
  });
}

/** Reads the claims through getClaims (signature-checked); any error means "no proof" (fail closed). */
export async function hasRecoveryProof(supabase: SupabaseClient, nowSec: number = Math.floor(Date.now() / 1000)): Promise<boolean> {
  try {
    const { data, error } = await supabase.auth.getClaims();
    return !error && hasRecentEmailProof(data?.claims, nowSec);
  } catch {
    return false;
  }
}
```

```ts
import type { SupabaseClient } from '@supabase/supabase-js';
import { isRateLimited } from '@/lib/auth/mfa';
import { passwordStrength, type PasswordError } from '@/lib/auth/password-rules';
import { hasRecoveryProof } from '@/lib/auth/recovery';

// Change password (Settings → Security) and set a new password after a recovery link (Plan 16b).
// Callers have already run requireOwner() (aal2 + owner). Results are error KEYS only: no Supabase text, no password, ever.
export type PasswordResult = { ok: true; othersSignedOut: boolean } | { ok: false; error: PasswordError };

function validate(next: string, confirm: string, email: string | null): PasswordError | null {
  if (!next || !confirm) return 'missing_fields';
  if (next !== confirm) return 'mismatch';
  return passwordStrength(next, email).issue ? 'weak' : null;
}

function updateError(e: { status?: number; code?: string }): PasswordError {
  if (e.code === 'same_password') return 'same_password';
  if (e.code === 'weak_password') return 'weak';
  return isRateLimited(e) ? 'rate_limited' : 'unexpected';
}

async function quietSignOut(client: SupabaseClient, scope: 'local' | 'others' | 'global'): Promise<boolean> {
  try {
    const { error } = await client.auth.signOut({ scope });
    return !error;
  } catch {
    return false;
  }
}

export interface ChangeInput {
  userId: string;
  email: string | null;
  current: string;
  next: string;
  confirm: string;
}

/**
 * Proves the CURRENT password on a separate, memory-only client (`checkClient()`: never the cookie session), revokes
 * that check session at once, then updates the owner session's password and signs every OTHER session out.
 */
export async function changePassword(session: SupabaseClient, checkClient: () => SupabaseClient, input: ChangeInput): Promise<PasswordResult> {
  if (!input.current) return { ok: false, error: 'missing_fields' };
  const invalid = validate(input.next, input.confirm, input.email);
  if (invalid) return { ok: false, error: invalid };
  if (input.next === input.current) return { ok: false, error: 'same_password' };
  if (!input.email) return { ok: false, error: 'unexpected' };
  try {
    const check = checkClient();
    const { data, error } = await check.auth.signInWithPassword({ email: input.email, password: input.current });
    if (error) return { ok: false, error: isRateLimited(error) ? 'rate_limited' : 'wrong_password' };
    const sameUser = data?.user?.id === input.userId;
    await quietSignOut(check, 'local'); // the check session must not linger (`others` below revokes it again)
    if (!sameUser) return { ok: false, error: 'unexpected' };

    const { error: updateErr } = await session.auth.updateUser({ password: input.next });
    if (updateErr) return { ok: false, error: updateError(updateErr) };
    return { ok: true, othersSignedOut: await quietSignOut(session, 'others') };
  } catch {
    return { ok: false, error: 'unexpected' };
  }
}

/**
 * The reset page's save: needs a session that proved the inbox in the last 15 minutes (the recovery claim, checked
 * again here, not only on the page), then signs out EVERY session, this one included: the owner signs in afresh.
 */
export async function setNewPassword(session: SupabaseClient, input: { email: string | null; next: string; confirm: string }, nowSec?: number): Promise<PasswordResult> {
  if (!(await hasRecoveryProof(session, nowSec))) return { ok: false, error: 'link_expired' };
  const invalid = validate(input.next, input.confirm, input.email);
  if (invalid) return { ok: false, error: invalid };
  try {
    const { error } = await session.auth.updateUser({ password: input.next });
    if (error) return { ok: false, error: updateError(error) };
    return { ok: true, othersSignedOut: await quietSignOut(session, 'global') };
  } catch {
    return { ok: false, error: 'unexpected' };
  }
}
```

```ts
'use server';

import { cookies } from 'next/headers';
import { FORGOT_COOKIE, FORGOT_LIMIT, attemptCookieOptions, bumpAttempts, isLimited, readAttempts } from '@/lib/auth/attempts';
import { isValidEmail, requestPasswordReset, type ForgotState } from '@/lib/auth/recovery';
import { createServerSupabase } from '@/lib/supabase/server';

/** Public (signed out). Same answer for every valid email: the account's existence is never revealed. */
export async function requestResetAction(_prev: ForgotState, formData: FormData): Promise<ForgotState> {
  const store = await cookies();
  const attempts = readAttempts(store.get(FORGOT_COOKIE)?.value, Date.now(), FORGOT_LIMIT);
  if (isLimited(attempts, FORGOT_LIMIT)) return { status: 'cooldown' };
  const email = String(formData.get('email') ?? '');
  if (!isValidEmail(email)) return { error: 'invalid_email' };
  store.set(FORGOT_COOKIE, bumpAttempts(attempts), attemptCookieOptions(FORGOT_LIMIT));
  await requestPasswordReset(await createServerSupabase(), email);
  return { status: 'sent' };
}
```

```tsx
'use client';

import { useActionState, useState } from 'react';
import { useTranslations } from 'next-intl';
import { PasswordInput } from '@/components/auth/PasswordInput';
import { FormField } from '@/components/shared/FormField';
import { LoadingButton } from '@/components/shared/LoadingButton';
import { passwordStrength, type PasswordFormState } from '@/lib/auth/password-rules';

const LEVELS = ['weak', 'fair', 'good', 'strong', 'veryStrong'] as const;
const EMPTY = { current: '', password: '', confirm: '' };

/**
 * New password + confirm with a strength meter; `withCurrent` adds the current-password field (Settings → Security).
 * Used by Settings (change) and /login/reset (after a recovery link). The server decides; the meter only guides.
 */
export function PasswordForm({
  action,
  email,
  withCurrent,
  submitLabel,
}: {
  action: (prev: PasswordFormState, formData: FormData) => Promise<PasswordFormState>;
  email: string | null;
  withCurrent: boolean;
  submitLabel: string;
}) {
  const t = useTranslations('auth.password');
  const ts = useTranslations('auth.security');
  // controlled: React resets uncontrolled fields after every action, which would wipe them after a wrong current password
  const [values, setValues] = useState(EMPTY);
  const [state, formAction, pending] = useActionState(async (prev: PasswordFormState, formData: FormData) => {
    const result = await action(prev, formData);
    if (result.ok) setValues(EMPTY); // typed passwords never outlive a successful change
    return result;
  }, {});
  const strength = passwordStrength(values.password, email);
  const set = (key: keyof typeof EMPTY) => (e: React.ChangeEvent<HTMLInputElement>) => setValues((v) => ({ ...v, [key]: e.target.value }));
  const fieldError = (key: 'wrong_password' | 'weak' | 'mismatch') => (state.error === key ? t(`errors.${key}`) : undefined);
  const formError = state.error && !['wrong_password', 'weak', 'mismatch'].includes(state.error) ? t(`errors.${state.error}`) : null;

  return (
    <form action={formAction} className="flex flex-col gap-[var(--gp)]" noValidate>
      {/* lets password managers file the new password under the right account */}
      <input type="text" name="username" autoComplete="username" value={email ?? ''} readOnly hidden />
      {withCurrent ? (
        <FormField id="current-password" label={t('current')} error={fieldError('wrong_password')}>
          {(p) => <PasswordInput {...p} name="current" autoComplete="current-password" value={values.current} onChange={set('current')} />}
        </FormField>
      ) : null}
      <FormField id="new-password" label={t('new')} hint={t('rules')} error={fieldError('weak')}>
        {(p) => <PasswordInput {...p} name="password" autoComplete="new-password" value={values.password} onChange={set('password')} />}
      </FormField>
      {values.password ? (
        <div className="flex flex-col gap-1.5" data-testid="password-meter">
          <div className="grid grid-cols-4 gap-1" aria-hidden="true">
            {[1, 2, 3, 4].map((i) => (
              <span key={i} className={i <= strength.score ? 'h-1 rounded-full bg-primary' : 'h-1 rounded-full bg-muted'} />
            ))}
          </div>
          <p aria-live="polite" className="text-xs text-muted-foreground">
            {t('strength', { level: t(`levels.${LEVELS[strength.score]}`) })}
            {strength.issue ? ` ${t(`issues.${strength.issue}`)}` : ''}
          </p>
        </div>
      ) : null}
      <FormField id="confirm-password" label={t('confirm')} error={fieldError('mismatch')}>
        {(p) => <PasswordInput {...p} name="confirm" autoComplete="new-password" value={values.confirm} onChange={set('confirm')} />}
      </FormField>
      {formError ? (
        <p role="alert" className="text-xs text-destructive">
          {formError}
        </p>
      ) : null}
      {state.ok ? (
        <p role="status" className="text-sm text-muted-foreground">
          {state.othersSignedOut === false ? ts('passwordChangedOthersFailed') : ts('passwordChanged')}
        </p>
      ) : null}
      <LoadingButton type="submit" pending={pending} className="self-start">
        {submitLabel}
      </LoadingButton>
    </form>
  );
}
```

```tsx
import { useState, useTransition } from 'react';
import { useTranslations } from 'next-intl';

/** Signs out every session of the owner except this one (Supabase `signOut({ scope: 'others' })`). */

          {t('signedOutOthers')}
        </p>

        <p role="alert" className="text-xs text-destructive">
          {t('signOutOthersFailed')}
        </p>
      ) : null}
```
